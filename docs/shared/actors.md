# アクター（このシステムを使う人）と、使える機能

> 共通の文書（2026-11-19 に作成）。用語は [用語集](glossary.md)、全体は [INDEX.md](../INDEX.md)。機能の細かい仕様は、各行のリンク先（`docs/features/`）を見る。

## この文書のねらい

- **アクター**＝このシステムを使う人の立場。用語集の**役割**と同じものを指す。**11のアクター**（現場の8役割＋役員・社長・システム管理者）。ここでは、役割ごとに、**使える画面・機能**と、**やってよいこと／やらないこと**を1か所にまとめる。
- 画面の入口は、画面ごとに別のURL。**使える画面は役割で決まる**（部署とは別の項目）。
- **モックの限界**: いまのモックは、ログインしても**権限の分離をしていない**（何でも通る。ほかの役割の画面も開ける）。この文書は、**本来そうあるべき使い分け**を書いたもので、権限分離は本実装の課題（[production-gaps](production-gaps.md)）。

- **区分（一般・責任者）**（2026-11-19 に追加）: 現場の8アクターには、**一般**と**責任者**がある。責任者は、そのアクターの**まとめ役**（例: 鑑定士の責任者＝グループ全員の業績を見られる人）。**役員・社長・システム管理者には、この区分はない**。区分を持たないアクターがほかにあれば、その行は「（なし）」にする。
- **「仮」の部分**: 責任者・役員・社長・システム管理者の**使える機能は、まだ設計者に確認していない**。このため、「機能の使い分け」の表では、**責任者は一般と同じ**（決まっている違いだけ反映）、**役員・社長は閲覧のみ（△）**、**システム管理者はマスタ管理のみ**と置いてある（仮置き）。確定したら、表を直す。

## アクターごとの、使える機能

### 鑑定士（鑑定士タブレット）

仕様: [tablet-auth-menu](../features/tablet-auth-menu/spec.md)・[tablet-dashboard](../features/tablet-dashboard/spec.md)・[tablet-workday-expense](../features/tablet-workday-expense/spec.md)・[tablet-schedule](../features/tablet-schedule/spec.md)・[tablet-visit](../features/tablet-visit/spec.md)・[tablet-customer-search](../features/tablet-customer-search/spec.md)・[tablet-customer-eval](../features/tablet-customer-eval/spec.md)・[warehouse-receiving](../features/warehouse-receiving/spec.md)

| 機能 | できること |
|---|---|
| ログイン | ID・パスワード、2段階認証、パスワードの再設定 |
| 業績ダッシュボード | 自分の業績、本社・グループリーダーからのメッセージ。**グループリーダーは、グループ全員・メンバー個別の業績も見られる** |
| 始業・終業・日報 | 前日繰越金の照合、点検、日報の提出（始業するまで、現地買取は使えない） |
| 今日の予定 | カレンダー・ルート表示。**配車係が確定した訪問だけ**が出る |
| 現地買取（訪問） | お客様確認 → 説明事項 → 買取明細（商品マスタ・AIカメラ・AI査定）→ 買取商品の確認 → シール紐づけ → GMOサイン送信・訪問終了。不在・日程変更などの記録 |
| 査定依頼 | 商品ごとに、査定員へ査定を頼む（任意）。チャットでやり取り |
| 顧客検索・お客様の評価 | お客様の履歴の検索、訪問ごとの評価・メモの登録 |
| 経費管理 | 経費（レシート写真つき）の計上、引き出し金額の入力、**補充の依頼**（経理部へ） |
| 商品の入庫 | 訪問で買い取った商品を、QRを読み取って倉庫に入庫 |

**やらないこと**: 確定・配車の変更（配車係の仕事）。**自分の記録は、マスタ管理では参照のみ**。

### オペレーター（コールセンター）

仕様: [callcenter-intake](../features/callcenter-intake/spec.md)・[visit-calendar](../features/visit-calendar/spec.md)・[callcenter-cooloff](../features/callcenter-cooloff/spec.md)・[store-reservation](../features/store-reservation/spec.md)

| 機能（メニュー） | できること |
|---|---|
| 受電 | **今日配布のチラシ（マーケティング部が登録）を見て、どこからの電話が増えそうかを見込む**。電話番号から、新規の受付か予約の変更かを判定。聞き取り（ヒアリング）、訪問先のエリア判定、鑑定士の空き確認、担当鑑定士の仮決定、**仮確定**。予約の日時変更・取消 |
| 訪問カレンダー | エリアごとの訪問の予定（週・日別）の確認、前日確認の連絡の記録 |
| クーリングオフ | お客様からの受電と、**依頼の作成**、倉庫の対応の進み具合の確認。倉庫とのチャット |
| 来店予約（店舗） | 店舗・日時を決めて、店舗への来店予約を受ける（仮確定・確定・配車はない） |

**やらないこと**: **確定は、しない**（仮確定まで）。お客様には、**鑑定士の名前を伝えない**（日時だけ）。クーリングオフの返送・完了は倉庫の仕事。

### 配車係（コールセンター・配車確定）

仕様: [dispatch](../features/dispatch/spec.md)（2.3）・[visit-calendar](../features/visit-calendar/spec.md)

| 機能 | できること |
|---|---|
| 配車確定 | 鑑定士ごとの列のカレンダーで、仮確定の訪問を**確定**（1件ずつ、または1日分まとめて）。**ドラッグで、鑑定士・時間を調整**。訪問の詳細（受付の内容すべて）の確認、**仮に戻す**、詳細の変更、取消。主に**翌々日分を毎日** |
| 判断の材料 | 鑑定士のランク・性別・今月の担当件数、移動距離（走行距離）、お客様の詳細（買取履歴・評価・ランク・厄介度・クーリングオフ歴）、休みとの重なりの警告 |
| お客様の評価の登録 | 顧客ランク・厄介度の登録・変更 |
| 訪問カレンダー | オペレーターと同じ訪問の予定の確認 |

**やらないこと**: 何を入力・変更しても、**状態は変えない**（確定済みは確定のまま）。お客様に連絡して回答次第にしたいときだけ、意図的に「仮に戻す」。

### 査定員（査定部）

仕様: [appraisal-hq](../features/appraisal-hq/spec.md)

| 機能 | できること |
|---|---|
| 今日の予定・訪問状況 | 担当グループ（A または B）の鑑定士の、今日の予定（時系列）と訪問状況を見る |
| 買取明細のリアルタイム表示 | 鑑定士が登録した商品・金額・ランク・数量・お客様の評価などを確認 |
| 査定依頼のチャット | 商品ごとに、鑑定士のチャットへ回答し、**完結**する |
| 承認／差戻し | 商品の買取を承認または差戻し（査定依頼があるときは、完結してから） |
| お知らせ送信 | 全員／グループ宛のメッセージを、鑑定士のダッシュボードへ |
| **査定（高額品の確認・確定）** | 郵送で届いた紫・赤のシールの商品を、**シールのQRを読み取って**、鑑定士が登録した内容を確認し、**確定**する（商品名・ランクは直せる。**買取金額は、支払い済みなので直せない**）。**鑑定士（一般）が登録した高額品**が対象（鑑定士（責任者）は自分で確定できる。正式版の要件） |

査定部の画面は、**左メニューで、「鑑定士サポート」（上の最初の4つ）と「査定」を切り替える**。

**やらないこと**: 現場には行かない。**経費は使わない**。入金・日報は経理部の仕事（査定部にはない）。

### 経理担当（経理部）

仕様: [accounting-expense-check](../features/accounting-expense-check/spec.md)・[accounting-balance](../features/accounting-balance/spec.md)・[accounting-fixed-weekly](../features/accounting-fixed-weekly/spec.md)

| 機能（メニュー） | できること |
|---|---|
| 経費精算 | 日ごと・鑑定士ごとに、経費・お客様への支払・現金の入力漏れ・ミスを**一次チェック**（チェック済み／差戻し）。**営業サポートの操作もここ** |
| 残高・入出金管理 | 日次残高、入金・支払の登録、**鑑定士の補充金**の入力、補充の依頼へのやり取り、お客様への支払 |
| 週間収支 | 週単位の入出金・粗利・固定費・残高。固定費の登録 |

**やらないこと**: 補充金の実際の振込（銀行システムで行う。このシステムは金額・結果を扱わない）。

### 倉庫担当（倉庫・物流）

仕様: [warehouse-stock](../features/warehouse-stock/spec.md)・[warehouse-receiving](../features/warehouse-receiving/spec.md)・[warehouse-sales](../features/warehouse-sales/spec.md)・[warehouse-cooloff](../features/warehouse-cooloff/spec.md)・[warehouse-packing](../features/warehouse-packing/spec.md)

| 機能（メニュー） | できること |
|---|---|
| 商品管理 | 在庫の確認・検索（商品名・シールNo.・お客様名）、QR読取、履歴の確認 |
| 入庫 | 届いた商品の入庫、シールの貼り替え |
| 倉庫間移動 | 他の倉庫へ送る・受け取る |
| 販売（出品） | フリマ・業者への出品、委託、売却の登録（クーリングオフの保管期間中は出品不可） |
| 売上管理 | 売上・利益（会社全体も） |
| クーリングオフ返品 | 依頼の一覧・チャット・回答・**返送・完了**（依頼の作成はコールセンター） |

**所属**: いずれかの倉庫に所属（**本社に所属する人も倉庫担当**）。倉庫マスタの編集は、マスタ管理で行い、倉庫・物流の画面にはない。

### 店舗スタッフ（店舗）

仕様: [store-purchase](../features/store-purchase/spec.md)・[store-reservation](../features/store-reservation/spec.md)・[gmosign](../features/gmosign/spec.md)

| 機能 | できること |
|---|---|
| 来店の一覧 | 待ち・対応中・これから来店の予約・完了の確認。**予約なしの来店（飛び込み）の受付**（お名前だけ） |
| 店頭買取 | お客様確認（本人確認・台帳の項目）→ 説明事項 → 買取明細 → シール → 確認・支払い（GMOサインへ送信）。来店ごとに、途中から再開できる |

**やらないこと**: お客様の自宅へは行かない。エリア判定・担当鑑定士の割り当て・配車はない。**店頭買取は、クーリング・オフの対象外**。**所属は、いずれかの店舗**。

### マーケティング担当（マーケティング部）

仕様: [marketing-flyers](../features/marketing-flyers/spec.md)

| 機能（メニュー） | できること |
|---|---|
| チラシ | チラシの登録・変更・有効/無効（ID・配布方法・広告種別・配布するエリア・期間・部数・費用）。IDは、システムが採番 |
| 配布カレンダー | 日ごとに、どのチラシを配るかを、月の表で見る（見るだけ） |
| 反響管理 | どのチラシが効果的だったかを、受付の件数・反響率・1件あたりの費用で見る（配布方法ごとの合計、効果の順、日ごとの受付） |

**やらないこと**: 受付・配車・買取の操作はしない（反響は、コールセンターの受付の記録を**見るだけ**）。チラシのデザインそのものの作成・保存は、まだこのシステムでは扱わない（[R-6](../FUTURE_REQUIREMENTS.md)）。

### システム管理者（マスタ管理）

仕様: [master-employees](../features/master-employees/spec.md)・[master-organization](../features/master-organization/spec.md)・[master-trips](../features/master-trips/spec.md)・[master-stores](../features/master-stores/spec.md)・[master-warehouses-vendors](../features/master-warehouses-vendors/spec.md)

| 機能（メニュー） | できること |
|---|---|
| 社員 | オペレーター・配車係・査定員・経理担当・倉庫担当・店舗スタッフ・マーケティング担当の登録・変更・有効/無効（**役割は、登録のときに決め、あとから変えられない**。鑑定士は参照のみ） |
| 部署・営業所 | 部署、営業所と担当の都道府県 |
| 出張 | 営業所のない都道府県への出張と、出張メンバー（期間中は、エリア判定・担当候補に「出張中」で出る） |
| 店舗・倉庫・委託先 | 店舗、倉庫・保管場所・高額品の判定、委託先（業者オークションなど） |

削除はなく、**有効・無効だけ**。**役割は、システム管理者が登録する**（モックでは、誰でも開ける）。

### 役員・社長

**経営の状況を見る人**（一般・責任者の区分なし）。**今のところ、閲覧のみ**（仮）: 業績・経理（収支）・倉庫（在庫・売上）・査定部・店舗の状況。現場の操作（確定・承認・登録など）はしない。専用の画面は、まだない（本実装の要件）。

## 機能の使い分け（縦＝アクター、横＝機能）

**○**＝できる（操作する）／**△**＝見るだけ・一部／**×**＝できない（使わない）。**画面（部署）ごとに表を分けている**。**区分**の「一般」「責任者」は、「この文書のねらい」を見る。

> **注意（仮置き）**: 責任者・役員・社長・システム管理者の行は、設計者に確認するまで**仮**（「この文書のねらい」）。**一般の行（鑑定士〜店舗スタッフ）は、いまの仕様どおり**。モックでは、どの画面も、誰でも開ける（権限の分離は本実装）。

## システムを使わない関係者・外部システム

アクターではない（このシステムの画面を使わない）。

| 名前 | 関わり |
|---|---|
| **お客様** | 商品を売る人。電話・来店・訪問で接する。システムは使わない。**クーリングオフの通知は郵送**（依頼は、コールセンターが電話で受けて作る） |
| **購入者** | 倉庫が商品を売る相手（フリマ・業者）。システムは使わない |
| **委託先** | 業者オークションなど、委託販売をお願いする業者 |
| **GMOサイン**（外部） | 契約書の電子契約。鑑定士・店舗スタッフが送信する（モックはダミー） |
| **銀行システム**（外部） | 補充金の実際の振込。このシステムは、振込の金額・結果を扱わない |
| **Googleマップ**（外部） | 訪問先の地図・ピン |
