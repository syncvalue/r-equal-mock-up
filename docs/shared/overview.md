### 0.2 業務の流れ（全体）

```
お客様の電話
  → [コールセンター] 聞き取り・エリア判定・担当鑑定士の仮決定 ＝ 仮確定（オペレーター）
  → [配車確定] 配車係が翌々日分などを確定
  → [鑑定士タブレット] 予定に出る → 始業 → 訪問 → 現地買取 → 訪問終了
        ├ 査定は [査定部] が承認・助言
        └ 契約書は [GMOサイン] で印刷し、紙で署名
  → 持ち帰り（入庫）→ [倉庫・物流] 保管（10日間はクーリングオフ期間）
  → 出品・委託・直接販売 → 購入者・業者へ発送 → 売上・利益の管理
  → （クーリングオフ）お客様の電話 → [コールセンター] 依頼を作成 → [倉庫] 回答・返送 → 返金の確認で完了
  → 終業・日報 → [経理部の経費精算] で営業サポートが、翌日以降に、経費（領収書）・お客様への支払・現金を一次チェック

お客様の来店予約（電話）→ [コールセンター] 店舗と日時を受け付ける（来店予約。仮確定・配車はない）
お客様の来店（予約あり・飛び込み）→ [店舗] 受付 → お客様確認・説明・査定・シール・契約書・代金のお支払い ＝ 店頭買取
  → 入庫待ち → [倉庫・物流] 入庫（買取のその日から出品できる。10日間の保管期間はない）
```

### 0.3 技術と構成

- Vite + vanilla JS（フレームワークなし）+ Tailwind CSS（CDN。**ネット接続が必要**）。
- 画面間の連携は、同一ブラウザの localStorage を介します（別タブで開いて確認）。キーは `src/store.js` に集約。
- ロジックは `src/` に純関数として置き、`tests/` で検証します（開発ルールは9章）。画面は各ディレクトリ（`callcenter/`・`honsha/`・`accounting/`・`warehouse/`・`master/`・`store/`・`gmosign/`・`tablet/`）。
- 各画面下部の「（デモ用）データ初期化」で、マスタ以外を消せます。マスタ管理のデータ（社員・部署・営業所・出張・店舗・倉庫・委託先。7章）は消えません。
- 起動は `docker compose up --build`（http://localhost:5173）。Docker を使わない場合は `npm install` のあと、`package.json` の dev スクリプトで開発サーバーを起動。テストは `npm test`。

### 0.4 ダミーであるもの（本実装で置き換える対象）

| 対象 | 現状 |
|---|---|
| ログイン（鑑定士・倉庫担当・店舗スタッフ。マスタ管理の社員のログインIDを使うのは、倉庫担当と店舗スタッフ） | ID・パスワードは何でも通る。SMSは送らず画面に認証コードを表示 |
| AI査定・レシートOCR・AIカメラ | 画像のハッシュから、それらしい値を返すだけ（`src/ai.js`） |
| 通話の文字起こし→項目入力 | キーワード・正規表現による簡易抽出（`callcenter/transcript.js`）。音声認識は無い |
| QRカメラ読取 | 実カメラは使わず、読み取ったように見せる |
| 商品マスタ・鑑定士の業績・予定・顧客履歴・倉庫・手数料率・配送CSVの列 | すべてダミー |
| 郵便番号 → 住所の候補 | 主な町域だけの小さな表（`src/zipAddress.js`）。本実装では日本郵便の郵便番号データか検索サービスに置き換える |
| 地図・距離 | 都道府県ごとの代用座標による概算（`src/dispatch.js`） |
| GMOサイン | 実サービスとは無関係の画面 |
