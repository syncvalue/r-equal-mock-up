# 画面共通のルールと、横断的な決定事項（UI・表記・画面ID）

> 機能仕様書の分割後の文書。元の仕様書の章番号（0.3.1・0.3.2・0.3.3・0.3.4・8）は、ほかの章からの参照のため、見出しのまま残してある。入口は [INDEX.md](../INDEX.md)。

### 0.3.1 補足説明は「?」にまとめる（画面共通）

- **画面に常時出す文字は、値・ラベル・状態・警告に絞る**。操作の手順・仕組み・理由・注記などの補足説明は、見出しやラベルの横の「?」アイコンにまとめ、**押す（タップする）と吹き出しで表示**する。見たい人だけ押せばよく、慣れた人の邪魔にならない。
- 吹き出しは、もう一度「?」を押す・ほかの場所を押す・Escキー・スクロールで閉じる。画面の端ではみ出さないよう位置を寄せる。
- **「?」にしないもの**: エラー・警告・取り返しのつかない操作の確認、短い空状態（「ありません」）、入力を促す短い指示、お客様に読み上げる・見せる必要がある文言（クーリング・オフの説明事項など）、印刷物の本文。
- **そもそも不要な注釈は書かない**。なくても分かる説明（ラベルの言い換え、括弧書きの補足、ボタンの下の念押しなど）は「?」にもせず削除する。「?」は、知りたい人がいそうな説明だけに使う。
- 実装は `src/help.js`（`helpIcon(text)` と、各画面の起動時に呼ぶ `initHelp()`）。新しい補足説明を足すときも、本文に書かず `helpIcon` を使う。

### 0.3.2 色とアイコン（画面共通）

- **使う色は4色だけ**: **グレー**（基調・文字・枠）／**ティール**（主な操作・成功・選択中）／**赤**（警告・エラー・取消）／**黄**（注意・保留）。青・紫・水色・緑・橙は使わない。色を増やすと、どの色も目立たなくなる。
- **文字色は、グレー（濃い・中くらい・薄い）・ティール・赤・黄・白**に絞る。
- **アイコンは、モノトーンの線画**（`src/icons.js` の `icon(名前)`。色は文字色に従う）を、メニューなど、必要な所だけに使う。**カラフルな絵文字は使わない**。見出し・ボタン・文言の飾りの絵文字は書かない。使ってよい記号は ✓ ✕ ⚠ ☑ ☐ ★ ☆ ☰ ✎ ▶ ＋ など、文字として表示されるもの。
- **例外**: ①訪問カレンダー（2.7）の**鑑定士ごとの帯の色**は、人を見分けるための色なので、4色に入らない色を使う（`src/staffColor.js`）。②配車確定（2.3）の**ランクの色**（SS＝赤・S＝橙・A＝緑・B＝青、不明＝薄いグレー。`src/rankColor.js`）と、お客様の**性別記号**（♀＝ピンク・♂＝水色）。ランク・性別を、ひと目で見分けるための色。**ランクの札（鑑定士・顧客）は、どの画面でも、このランクの色**を使う。シールの色（紫・赤・黄・緑・青）は業務上の意味がある色なので、丸（🟣🔴🟡🟢🔵）のまま出す。ダミー画像・顔写真の中の色は対象外。

### 0.3.3 デモ専用の部品（画面共通）

- **デモを円滑に進めるために仮で置いているボタン・リンク**（データ初期化、ダミー写真、サンプル写真、まとめてチェック、デモ用の電話番号、デモ用アカウント、音声入力デモ、他の画面へのリンクなど）は、**本番では消える部品**。**すべて同じ見た目（`demo-only`。`src/theme.css`）**にする: **小さく・薄いグレー・破線の枠・背景なし**で、先頭に「デモ｜」が付く。**存在感を消し、本来のボタンと明らかに違って見える**ことを守る。
- 新しくデモ用のボタン・リンクを足すときは、色や形を考えず、`class="demo-only"` を付ける（「（デモ用）」と文言に書かない。「デモ｜」は自動で付く）。
- デモ用の電話番号（受電画面）は3つに絞る: 予約・買取あり／買取のみ／新規。

### 0.3.4 入力例（プレースホルダー）

- 入力欄の入力例は、入力済みの文字と見間違えないよう、**薄い灰色**で出す（全画面共通。`src/theme.css`）。

## 8. 横断的な決定事項（UI・表記）

- **端末**: 鑑定士タブレットは iPad Pro（縦・横）に合わせる。**業務画面は文字小さめ、お客様に見せる画面は大きめ**。ダークモードあり。
- **表記の統一**: 人・組織・業務の言葉は、冒頭の**用語集**にそろえる。数量は「点」、「マスタ」、「繰越金」、「（デモ用）」表記。不自然な日本語（例: 始業開始）は避ける。文言は短く簡潔に。
- **「ダミー画面」の表示**: ヘッダーに「ダミー画面（PC）」などの表示を出すのは、**GMOサイン（外部サービスの代わりのダミー）だけ**。ほかの画面（コールセンター・鑑定士タブレット・店舗・倉庫・物流・査定部・経理部・マスタ管理）は、本物の業務画面なので、出さない（ブラウザのタブの名前にも「（ダミー）」は付けない）。
- **画面ID**: **全画面（ページ・タブ・同じ画面の中の状態・手順・モーダル・ドロワー・印刷用）に、画面IDを振る**。クライアントからの修正依頼で、どの画面かを伝えるため。形式は「アプリの記号＋番号」（コールセンター `CC`・鑑定士タブレット `TAB`・店舗 `STR`・倉庫・物流 `WH`・査定部 `HQ`・経理部 `ACC`・マスタ管理 `MST`・GMOサイン `GMO`・画面一覧 `LNC`）。**ページ・タブは `CC-01`、同じ画面の中の状態は `CC-01-1`、モーダル・ドロワーなど重ねて出す画面は `CC-M01`、印刷用は `WH-P01`**。**いまの画面のIDは、画面の左下に、いつも出す**（印刷には出さない）。**モーダル・ドロワーは、その中にも、IDの札を出す**。一覧は `docs/SCREEN_IDS.md`（`src/screenIds.js` の表から `node scripts/gen-screen-ids.mjs` で作る）。**新しい画面・モーダルを足すときは、表にIDを足す**。ブラウザの確認ダイアログ・トーストには振らない。
- 金額入力欄は通貨形式（¥・円・3桁区切り）。数字は右詰め。
- 画面一覧のリンクは別タブで開く。コールセンターは `?tab=dispatch`・`?demo=1`・`?area=`・`?day=` で直接開ける。
