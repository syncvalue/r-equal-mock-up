## 3. 査定部（`/honsha/index.html`）

**画面の構成（2026-11-19）**: 経理部・鑑定士タブレットなどと同じ**開閉式の左メニュー**（☰）で、機能を切り替える。メニューは2つ: **鑑定士サポート**（これまでの査定部の機能。3.1）と、**査定**（高額品の確認・確定。3.2）。ヘッダーに「査定部 › 機能名」を出す。メニューのバッジは、鑑定士サポート＝返信待ちの査定依頼、査定＝査定待ちの商品の件数。査定員の切り替えは、どちらの機能でも使う。

### 3.1 鑑定士サポート

- **担当**: 査定員（青木=グループA、井上=グループB。マスタ管理の社員で登録、7章）が、担当グループの鑑定士の**今日の予定（時系列）と訪問状況**を見る（デモ用に査定員を切り替え可。完了した訪問は隠せる）。**いま訪問中の予定は、行全体を緑の背景・左の太い緑の線・点滅する「● 訪問中」のバッジで目立たせる**（**完了は、灰色の背景・左の灰色の太い線・「✓ 完了」の濃い灰色のバッジで、完了したことが一目で分かるようにする**。まだは白地のまま）。
- **訪問予定の事前確認（2026-11-19）**: 左の一覧で、**まだ訪問していない予定（訪問の記録がない予定）を押すと、モーダルで、その予定の詳細が開く**。査定員が、訪問前に、**どういったお客様かを確認する**ためで、**見るだけ**（入力・登録・訪問の開始はない。Esc・外側・「閉じる」で閉じる）。出す内容: 日時・担当の鑑定士・お客様（顧客ランク・新規／リピーター・厄介度・クーリングオフ歴）・今回の予定（住所・電話・商材・受付）・お客様の評価・査定したが売らなかったもの・過去の買取履歴（品目・金額・鑑定士の評価）・受電時のヒアリング・前日確認の記録。訪問が始まった予定は、これまでどおり、押すと買取明細が開く。
- **買取明細のリアルタイム表示**: 鑑定士が登録した商品・買取金額・**想定販売価格**・ランク・数量・売る/売らない・本社査定の状況・コメント。**鑑定士のお客様の評価**も確認できる。
- **査定依頼のチャット**: 商品を選ぶと、鑑定士とのチャットが開く（鑑定士は左、査定員は右。写真・「既読」つき）。**普通のチャットと同じ**で、メッセージを入力して「返信する」（Ctrl+Enter でも送れる）。査定部はPCなので、**タグ・定型文のボタンはない**。任意で**提案査定額（買取金額）**と**想定販売価格**を付けられる（ランクは鑑定士の入力のまま。**どちらか一方だけでも送れる**。入力欄は返信フォームに2つ並ぶ。数量分の合計）。鑑定士は、提案を商品に**反映**できる（提案に入っている項目だけ）。**査定員は、ここ（査定依頼のとき）と、「査定」（3.2）の両方で、想定販売価格を入れられる**。チャットと違うのは、査定依頼ごとに**「完結する」**操作がある点だけ。**送信フォームは1つ**（回答と意見の区別なし）。鑑定士の返信が未読の商品は、一覧に「未読あり」が出る。**査定員が「完結する」**とやり取りが終わる。完結のあとに鑑定士が続けて送ると、再開（返信待ち）になる。査定依頼のない商品へのコメントは、これまでどおり鑑定士のコメントとして届く。
- **承認／差戻し**: 鑑定士の申請は不要で、**商品が登録された時点からいつでも**実行できる。金額が入っていない商品は対象外。**査定依頼が出ている商品は、完結するまで承認できない**（ボタンは押せず、一覧には「査定の完結待ち」）。**承認の欄は、チャットの上に固定で表示**し、査定依頼が続いている間は、隠さずに**マスク**（薄く表示して操作不可）する。**差戻しも、完結してから**。依頼のない商品は、いつでも承認できる。「承認できるN件を一括承認」は、条件を満たす商品だけ。**差戻しは理由必須**で、鑑定士にはコメントとしても届く。承認後に鑑定士が変更したら再承認が必要。
- **お知らせ送信**: 全員／グループ宛のメッセージを作成して、鑑定士のダッシュボードに表示。
- 入金・日報の機能は**経理部へ移した**（査定部にはない）。

### 3.2 査定（高額品の確認・確定）

- **業務の前提**: **紫・赤のシールの商品（貴金属などの高額品）は、専門の知識がある査定員でないと査定できない**。知識のない鑑定士（一般）が現場で登録した内容を、**査定員が、あらためて確認して確定する**。この確認・確定が「査定」。
- **流れ**: 商品（シール付き）が**郵送で届く** → 開封し、**シールのQRを読み取る**（シールNo.の入力でもよい。カメラはモック） → 鑑定士が**登録した内容**（お客様・鑑定士・買取日・カテゴリ・ランク・買取金額・想定販売価格・写真）が出る → **実物と見比べて、正しいか確認**（違っていれば、商品名・ランク・**想定販売価格**を直す。**買取金額は直せない**） → **「この内容で、査定を確定する」**。
- **一覧**: 左に、**査定待ち／確定済み**の一覧（買取の古い順）。**検索欄**（商品名・シールNo.・お客様の名前。入力のたびに絞り込む）もある。**シールを読み取るか、一覧から検索して選ぶか**、どちらでも該当の商品を開ける。選ぶと、読み取ったのと同じ確認の画面が開く。紫・赤の判定は、倉庫マスタの高額品の色（`highValue`）と同じ。ほかの色（黄・緑・青）は、査定の対象外（読み取ると、その旨を出す）。貼り替え済みの古いシールを読み取ったら、新しいシールNo.を案内する。
- **確定すると**: 商品に、確定した査定員・日時・**訂正した内容（項目・前→後）**が残る（`appraisal`）。訂正した内容は、商品の名前・ランク・想定販売価格にも反映する（想定販売価格は、未入力から入れる・変えるのどちらもできる。0は未入力）。**買取金額は変えない**（**想定販売価格は、直せる。販売の見込みで、お客様への支払いに関係しないため**。買取金額は、**お客様には、買取の時点で支払い済みで、あとから変わることはない**ため。画面では「支払い済み・変更できません」と出す）。確定済みは、取り消せない（モック）。1点ずつ（シール1枚＝1点）確認する。
- **鑑定士の区分による違い（モックでは扱わない。正式版の要件）**: **鑑定士（責任者）は、自分の権限で確定まで進められる**（査定部の確認は要らない）。**鑑定士（一般）は、登録時は未確定で、あとで査定部が確認して確定済みにする**。モックでは、区分の違いは扱わず、**紫・赤の商品は、すべて査定待ちとして出す**。→ [今後の要件 R-5](../../FUTURE_REQUIREMENTS.md)
- **モックの限界**: 商品が届いたこと（郵送の受け取り・入庫）とは連動しない（倉庫の入庫・倉庫間移動とは別に、確認できる）。訪問の買取明細・鑑定士のタブレットには、確定の結果を戻さない。**ダミー**: 初めて査定部を開いたとき、紫・赤の商品（9点・お客様5人・複数の鑑定士）を自動で入れる（一度入れたら、確定して空になっても入れ直さない）。空のとき、「デモ用の査定待ちを入れる」ボタンでも足せる。
