## 11. 店舗（店頭買取）（`/store/index.html`）

**お客様が店舗に買取希望品を持ち込む**買取。訪問買取（1〜6章）と**別の流れ**で、**訪問・エリア判定・担当鑑定士の割り当て・配車・移動距離はない**。画面は `store/`、ロジックは `src/storeVisits.js`（来店）・`src/storeDraft.js`（買取の作業中の内容）・`src/storePurchase.js`（完了の記録）・`src/storeSession.js`（ログイン）・`src/storeSample.js`（見本）。用語は用語集（店舗・店舗スタッフ・店頭買取・来店・来店予約・飛び込み）のとおり。

> **店頭買取は、クーリング・オフの対象外**（法律上、対象は訪問購入のため。依頼者に確認して決定）。買い取った商品には、**10日間の保管期間（5.7）がなく、入庫したその日から出品できる**。
> 古物営業法に基づき、**本人確認**と、買取の記録に要る**氏名・住所・職業・生年月日**を、お客様確認で入力する。古物商の許可は店舗ごとに必要（7.7）。

### 11.1 ログインと画面の構成

- 店舗スタッフごとにログイン（`st01`〜。パスワードは何でも可。**店舗スタッフは、マスタ管理の社員（7.1）で登録する**）。**所属する店舗が、表示の対象**。受付・買取は、ログインした店舗スタッフの名前で記録される。
- 画面は、**来店（一覧）**と**買取（5手順）**の2つ。上部に、店舗名・日付・**今日の来店の集計**（来店の組数・買取の件数・成約率・買取額）が出る。成約率 ＝ 買取に至った数 ÷ 完了した数。**取消・来ずは来店に数えない**。
- 見本の来店は、記録が空のときだけ自動で入る（店舗ごとに、待ち・予約・完了）。「（デモ用）データ初期化」で来店の記録・作業中の内容が消える（店舗マスタは消えない）。

### 11.2 来店（一覧）

- **状態**: 予約 → 待ち（来店済み）→ 対応中（担当の店舗スタッフが付く）→ 完了。ほかに**取消**（理由つき。予約・待ちのみ）・**来ず**（予約の日になった予約だけ）。
- **予約**は、コールセンターの来店予約（2.6）から来る。店舗では、**来店済みにする**／**対応を始める**（来店済みを省いて、予約から直接でもよい）／来ず／取消ができる。
- **飛び込み**: 予約なしの来店。**お名前だけで受け付けられる**（電話番号は、聞ければ。過去のお客様を探す手がかり）。受け付けると「待ち」に並ぶ。
- 一覧は、待ち（来店順）・対応中・これから来店の予約（時刻順）・完了（買取の金額、または「見送り」）・取消と来ず。**過去のお客様には、顧客ランク・厄介度・クーリングオフ歴の印**が付く（電話番号が一致したとき）。
- 対応中の来店は、**どの店舗スタッフでも「買取を続ける」で開ける**（交代・引き継ぎのため）。作業の内容は、来店ごとに保存され、画面を閉じても続けられる。

### 11.3 買取の流れ（5手順）

鑑定士タブレットの現地買取（1.6）と同じ考え方で、店頭に合わせて整理した。

1. **お客様確認**: 初めて／リピーター（何回目）、過去の評価（顧客ランク・厄介度・クーリングオフ歴）、前に査定したが売らなかったもの（見送り品）を、スタッフが見る（お客様には見せない）。お客様の情報（**氏名・電話番号・住所・生年月日が必須**、フリガナ・予備の電話番号・郵便番号・職業）を、本人確認書類と照らして入力し、「確認した」にチェックして次へ。
2. **説明事項**（査定前に必須）: 5項目（買取の流れ・断れること・撮影と写真送信の了承・本人確認の必要性（古物営業法）・**店頭買取はクーリング・オフの対象外であること**）と、**他商品を提案してよいか**の回答（はい・いいえ）。
3. **買取明細**: 商品マスタから選ぶ（検索）。金額は**1点あたり（単価）**を入力。ランク・数量・**売る／見送る**を決める。見送る商品は契約に入らず、見送り品として記録される。**売る商品が1点もなければ、次へ進めない**（その場合は「買取に至らず終了（見送り）」）。
4. **シール**: 売る商品の**1点ごとに、シールNo.と色**（紫・赤・黄・緑・青）が必要（読み取りはモック）。同じシールを別の商品には使えない（入庫待ち済みのシールも）。紫・赤は高額品で、いったん倉庫に入庫してから本社へ移す（5.2）。
5. **確認・支払い**: 買取内容と支払い金額（**お客様には、お客様画面（11.6）に出して見せる**。店舗スタッフの画面は、お客様に見せない）。**契約をGMOサインへ送る**（本人確認書類の登録・契約書の印刷。チェック項目・署名は、印刷した紙にお客様が記入。6章）。そのあと、**終了前の確認6項目**（本人確認書類・契約書の記入・店舗控えの回収とお客様控えの手渡し・代金のお支払い・数量の一致・忘れ物）がすべて済むと、**買取を完了**できる。
   - **契約を送ったあとは、前の手順に戻れず、見送りにもできない**（契約書と食い違わないように）。
   - 訪問買取の「梱包・持ち帰り」「クーリング・オフの説明」は、店頭にないので、確認項目から除いた。

**買取に至らなかった場合**: どの手順からでも「買取に至らず終了（見送り）」で完了にできる。入力済みの商品は、すべて見送り品として記録され、成約率の分母（完了）に数えられる。

### 11.4 完了すると作られる記録

- **契約**: 訪問買取と同じ契約の記録（`channel: store`・店舗・来店のID）。GMOサイン（6章）で印刷でき、**お客様の履歴は電話番号で結びつく**ので、次回は「リピーター」になる（訪問買取・店頭買取をまたいで同じお客様として数える）。契約書の「新・再」と「鑑定士」は、リピーターか／担当の店舗スタッフ。
- **入庫待ち**: シールを貼った実物**1点ごと**（鑑定士の持ち帰りと同じ。5.2）。店頭買取の印・店舗・店舗スタッフが残る。倉庫・物流の「入庫」に出て、倉庫担当が入庫する（高額品の規則は5.2のまま）。倉庫の画面には、担当が「**なんば店・店舗スタッフ 田中 美咲**」のように出る（鑑定士の名簿では引かない）。
- **見送り品**: 売らなかった商品（売らなかった理由は聴取しない＝記録しない）。次回、お客様確認で出る。

### 11.6 お客様画面（2枚目のモニタ）（2026-11-19）

**店舗スタッフの画面（ノートPC）は、お客様に見せない**（顧客ランク・厄介度・クーリングオフ歴・過去の見送り品・シールNo.など、社内の情報が並ぶため）。そこで、**お客様に向けた専用の画面**を別に用意した。想定は**デュアルモニタ**: ノートPCの画面は店舗スタッフだけが見て、**もう1枚のモニタを、お客様に向ける**。

- **画面**: `/store/customer.html?store=<店舗ID>`（`store/customer.html`・`customerScreen.js`・`customerScreenView.js`。内容を作るロジックは `src/storeCustomerView.js`）。**見るだけの画面**で、ボタン・入力欄はない。文字は大きく、ダークモードにしない。
- **開き方**: 店舗スタッフの画面の上部の「**お客様画面を開く**」で、別のウィンドウが開く。ウィンドウを、お客様に向けたモニタへ移して使う。**ログインは要らない**（モック。正式版の要件は [R-7](../../FUTURE_REQUIREMENTS.md)）。
- **反映**: 買取の手順の上部の「**お客様画面へ反映**」を押したとき**だけ**、お客様画面が更新される（入力の途中の内容は、お客様に見えない）。**いまの内容がお客様画面に出ているか**（「✔ お客様画面に反映済み」／「お客様画面に未反映の変更があります」）が、店舗スタッフに分かる。
- **手順ごとに出る内容**（お客様に見せてよいものだけ）:
  | 手順 | お客様画面 |
  |---|---|
  | 来店の一覧・反映前・ログアウト後・見送りで終了後 | 「いらっしゃいませ」（待機。店舗名のみ） |
  | 1 お客様確認 | 「ご本人情報のご確認」: 入力したお名前・住所・生年月日などを、お客様がご自身で確かめる（未入力の欄は出さない） |
  | 2 説明事項 | 「ご説明」: お客様向けの文言で5項目（クーリング・オフの対象外を含む）。説明が済んだ項目に✔ |
  | 3 買取明細 | 「お買取の内容」: 商品名・状態（ランク）・数量・金額・合計。**見送る商品は「お売りにならない」**（合計に入らない）。金額が未入力の商品は「査定中」 |
  | 4 シール | 「商品のお預かりの準備をしております」（シールNo.・色は出さない） |
  | 5 確認・支払い | 「お支払い」: 売る商品と**お支払い金額**。契約を送ったあとは、契約書の案内 |
  | 買取の完了 | 「ありがとうございました」（反映の操作は要らず、自動で出る） |
- **お客様の情報を画面に残さない**: 来店の一覧へ戻る・見送りで終了・ログアウトのときは、**自動で「いらっしゃいませ」に戻す**。
- **連動のしかた（モック）**: 同じブラウザの中の保存（localStorage）で、ウィンドウどうしが連動する（店舗ごと）。別の端末へは届かない。
- 画面ID: 店舗スタッフの画面は STR-01〜07、**お客様画面は STR-08〜**（[画面ID一覧](../../SCREEN_IDS.md)）。

### 11.5 モックの範囲

連動は最小限（お客様画面は、同じブラウザの中だけ。11.6）。**レジ現金・査定部との連動・経理部・業績の店舗別・納入先の倉庫への連動・古物台帳**は、まだない（10章）。
