# コールセンター：受付と、仮確定後の変更・取消

> 機能仕様書（分割後）。元の仕様書の章番号（2・2.1・2.2・2.4）は、ほかの章からの参照のため、見出しのまま残してある。用語は [用語集](../../shared/glossary.md)、全体は [INDEX.md](../../INDEX.md)。

## 2. コールセンター（`/callcenter/index.html`）

運用の前提は次のとおり（依頼者からの指示。自動メモリにも記録済み）。**ここを外すと、後で連絡し直しが発生する。**

> **オペレーターは「仮確定」まで。** 担当鑑定士も仮決定で、**お客様には鑑定士の名前を伝えない**（日時だけ伝える）。
> **配車係が最終確定**する。主に**翌々日分を毎日**。確定した訪問だけが鑑定士タブレットの予定に出る。
> 受付関連の画面・文言では「確定」ではなく**「仮確定」**を使う。鑑定士名をお客様向けに出さない。

**画面の切り替え**: 受電・訪問カレンダー・配車確定・クーリングオフ・来店予約は、ヘッダーの横並びのタブではなく、**左の開閉式メニュー**（☰で開き、項目を選ぶか、外側・✕で閉じる。経理部・倉庫・物流・鑑定士のタブレットと同じ）で切り替える。ヘッダーに「コールセンター › 選んだ画面」と出す。メニューの項目に、訪問カレンダーの**前日確認の未連絡**の件数（2.7）・配車確定の**仮確定・変更**の件数・クーリングオフの**倉庫の回答待ち**の件数を出し、どれかあれば☰に点を出す（`callcenter/menu.js`）。件数のバッジは、項目名・説明の**下**に折り返して並べる（右に置いて、項目名を窮屈にしない。鑑定士タブレット・経理部・倉庫・物流のメニューも同じ）。

### 2.1 受付（オペレーター）

- **受電の入口は1つ**（メニューの「受電」。`?tab=new`）: 新規のお客様か、予約の変更のお客様かは、電話に出た時点では分からないので、**最初に電話番号だけを聞く**。番号（10〜11桁）が入ると、自動で分かれる。**電話番号は必須**（番号が聞けない受付はしない）。
  - **その番号で受け付け済みの予約がある**: 予約のカードが先頭に出る（**日時を変更・取消**。変更は、受付と同じ入力欄に内容が戻り、右のカレンダーで選び直す）。入力欄は出さず、「＋ 新しい受付として入力する」を押したときだけ出す（同じお客様が別の訪問を頼む場合）。
  - **訪問の履歴**（番号を入れると、予約の下に出る。`callcenter/phoneTimeline.js`）: 同じ番号の**訪問済みの受付・取消した受付・買取の記録**を、新しい順に1つの一覧にする（予約のない買取も入る）。1件ごとに、日付・内容・買取額（買取なしは「買取なし」、取消は「取消」と理由）。**買取のある回は、押すと品目ごとの内訳が開く**（担当した鑑定士・見送り品の点数つき）。上位3件を出し、残りは「さらにN件」。**買取が多い回も縦に伸びないよう、内訳は一定の高さでスクロールする**（行には点数だけ出す）。予約・訪問の履歴・お客様（引用）・受電履歴は、**1つの枠にまとめ、1件1行**で出す。電話をしながら「このあたり買い取っているな」と分かるためのもの。**これからの訪問は、変更・取消のボタンがある「訪問予定」の欄**（複数あれば全部）に出す。
  - **デモ用の電話番号**: 番号の欄が空のあいだ、欄の下に、控えめなボタン（0.3.3）が3つ出る（押すと入る）。予約2件＋過去の訪問3回（山田 花子）／予約なし・過去の買取だけ（小林 和子）／新規。
  - **顧客ID**（電話番号の横の欄）: **お客様は顧客IDで一意**にする（電話番号は変わる・2つある・ご家族と共有するため）。形は **C＋6桁**（例: C000101）。**電話番号を入れると、知っているお客様のIDが自動で入る**。**顧客IDは、システムが自動で採番**する（人は入力しない。欄は表示だけ）。知らないお客様は、**受付を確定するときに、次の番号を採番**する（受付の記録に残る。確定しなかった電話では採番しない）。受け付け済みの予約を直しているあいだは、IDを変えない。モックのため、IDの対応は受付の記録と過去のお客様（ダミー）から作る。
  - **予約はない**: 過去の買取・受電履歴があれば出し（「前回の内容を入力」で、お名前・フリガナ・郵便番号・住所を入れられる。入れたあとも直せる）、新規の入力欄を出す。過去の記録もなければ「この番号の受付・買取はありません」と出す。
  - 番号が入るまでは、電話番号の欄だけを出す。
- **入力欄は、電話番号のあと、聞く順に上から並べる**: ①来電のきっかけ → ②売りたいもの → ③お客様（電話番号2・お名前・フリガナ・性別・年齢・住所）→ ④訪問の希望日時 → ⑤確認・備考（立会い・大型品・その他・注意・ご同席者など）。聞き取り状況・不足項目の表示も、この順。**お名前とフリガナは、それぞれ1つの入力欄**（姓名・セイメイを分けない。空白で区切って入れてもよい）。
- **鑑定士指名**（2026-11-19）: お客様が鑑定士を指名しているときは、⑤確認・備考の「鑑定士指名」を押して印を付け、**右のカレンダーで指名の鑑定士を選ぶ**（聞き取りの必須項目ではない。ヒアリング項目の数には入らない）。**指名の予約は、配車確定でも、鑑定士を変えられない**（時間は変えられる。2.3）。受付の変更でも、同じ鑑定士のままで、日時だけ選び直せる。
- **ヒアリング項目**（`callcenter/intake.js`）: 電話番号1・2、お名前、フリガナ（必須）、性別（必須）、年齢（必須）、郵便番号、住所、希望日時、来電のきっかけ（チラシ）、売りたいもの、当日の立会い、ご同席者、大型品・その他、駐車スペース、表札、前日確認の連絡時間帯、訪問時の注意。
  - **必須（確定に必要）**: 電話番号・お名前・フリガナ・性別・年齢・住所・来電のきっかけ・売りたいもの。他は聞き忘れの注意だけ。
  - **聞き取り状況**（聞いた✔／未）を項目ごと・上部パネルに表示して聞き忘れを防ぐ。パネルは、白地に細い枠で、**進み具合の棒と「聞いた数／全体」を1行**に、残りの項目を**「必須」「任意」の2段**に分けて、丸いチップで並べる（必須は赤、任意は灰色。聞いた項目は出さない）。「なし」と聞いた場合も聞いた扱い。必須は赤い＊。右側の確定ボタンの上には、未入力・聞き忘れの一覧は重ねて出さない（聞き取り状況だけに一本化）。
  - **年齢を聞けなければ、声色から性別・年代を推測**して選べる。ただし**「推測」として区別して記録**する。
  - **顧客ランク（推測）**（③お客様の欄。任意。SS・S・A・Bから選ぶ）: **新規のお客様でも、顧客ランクを付ける**ため、住所（高級住宅街など）や話し方から、**オペレーターが推測して入れる**。受付の記録（`customerRank`）に残り、配車確定の帯の色になる。**配車係が、あとから直せる**（2.3。お客様の評価の登録）。登録・買取の実績から決まるランクがあれば、そちらを優先する。住所からの自動推測はしない（今後の要件 R-3）。
  - 立会いとご同席者は別項目。売りたいものは、メイン商材（背広・婦人服・婦人靴・紳士靴、数量帯）＋その他の商材＋詳細（複数行）。
- **問合せ種別と広告種別**（「来電のきっかけ」の最初の2つの選択欄）: **問合せ種別**は、お客様が問い合わせてきた手段（電話・店舗来店・催事・営業からの紹介依頼・HP（メール）・LINE・持ち込み。初期値は電話）。**広告種別**は、見た広告の種類（背広・婦人ふく・婦人くつ・紳士靴・店舗：香水・催事：香水（26.9月〜）・催事→店舗来店・昔のカメラ催事チラシ・昔の香水催事チラシ・昔のオーディオWEB広告・げんえきやHP・管理部修正済）。**広告種別は必須ではない**が、聞き取り状況には出す。受付の記録に残り、鑑定士・配車係の画面の「きっかけ」には、広告種別と、電話以外の問合せ種別が先頭に付く。
- **郵便番号から住所**: 郵便番号を7桁入れる（ハイフン・全角は可）と、**訪問先の住所の欄に、町域まで自動で入る**（番地は続けて入力）。1つの郵便番号に町域が複数あるときは、共通の頭の部分だけ入り、残りは欄の下の「住所の候補」のボタンから選ぶ（押すと住所に入り、カーソルが末尾に来る）。住所が空か、前の郵便番号から入れた町域のままのときだけ入れ、**打ち込んだ住所は消さない**（住所がすでに候補で始まっていれば、候補は出さない）。**入るのは提案で、住所は自由に直せる**。郵便番号は、まずモックの小さな表（`src/zipAddress.js`）を引き、**表にない番号は、郵便番号の検索サービス（zip-cloud。郵便番号だけを送る）で調べて**、結果をおぼえる（見つからなければ「見つかりません」、通信できなければ「調べられませんでした」。その場合は住所を直接入力する）。本実装では、日本郵便のデータに置き換える。
- **地図とピン**（お客様の欄の住所の横の「地図」）: 押すと、**右の画面（空きカレンダー）が、訪問先の地図に切り替わる**。**Googleマップ**（左上の「地図／航空写真」で切り替え。`callcenter/googleMap.js`。APIキー `VITE_GOOGLE_MAPS_API_KEY` がなければ、OpenStreetMapの地図。`callcenter/mapPane.js`）。住所が空なら、入力を促す。「カレンダーに戻る」で元に戻る。
  - **ピン**: **建物の位置を押すとピンが置け、ドラッグで動かせる**。置いた位置の**緯度・経度は、住所の下に、ラベル（入力欄ではない）で出す**（小数6桁。置く前は「位置：未設定」）。ピンは受付に記録され（日時変更で戻る）、置いてあれば、訪問先の位置（前の訪問からの距離・鑑定士の予定の地図）に、住所からの概算の代わりに使う。
  - **住所から自動で探す**: 地図を開くと、**入力した住所の場所へ、地図が自動で動く**（Googleのジオコーディング。キーがなければ、OpenStreetMapのNominatim。どちらも住所を送る）。番地で見つからなければ、番地を削って町域まで広げて探す。それでも見つからなければ「見つかりません」と出るので、地図を動かして探す。「住所から探す」で、もう一度探せる。
  - **仮のピン**: 地図を開いたとき、ピンがまだなければ、**検索した住所の位置に、ピンを仮に置く**（ラベルに「住所からの仮の位置」と出る）。**人がピンを置く・動かすまでは、地図を出したまま住所を打ち足す（番地など）と、少し待って、地図も仮のピンも、その場所へ連動して動く**。**人が置いたピンは、住所を変えても動かさない**（人の修正が優先）。地図のあいだは、入力しても地図そのものは描き直さない（動かすだけ）。
- **来電のきっかけ**: チラシは**固有のID**（N/P/D＋4桁）で特定する（広告の種類だけでは、どの号か決められないため）。IDのない広告（ネット・テレビ・紹介・再利用）のみ言葉から判定。IDの欄には**サジェスト**（入力に合わせて、ID候補と広告名が出る）があり、選ぶと入る。該当しないIDには「該当なし」とだけ出す。
- **過去のお客様**: 電話番号（1・2）が一致すれば、前回の内容を入力できる（入力補助。入れたあとも直せる）。買取の実績は、訪問の履歴で見る。**電話番号ごとの受電履歴**を表示。オペレーター向けの表示は最小限。
- **エリア判定**（`src/dispatch.js`）: 訪問先の**都道府県**から担当エリアを決め、そのエリアの鑑定士だけを候補にする（電話は全国から来るため、お客様の住所で判定）。

  | エリア | 都道府県 |
  |---|---|
  | 大阪 | 大阪・奈良・和歌山 |
  | 兵庫・京都 | 兵庫・京都・滋賀 |
  | 関東 | 東京・神奈川・埼玉・千葉・茨城・栃木・群馬 |
  | 東海 | 愛知・岐阜・三重・静岡 |

  担当のない都道府県は「対応エリア外」とし、他エリアの鑑定士を例外として選べる。**ただし、希望日に出張（7.4）がある都道府県は、出張エリアとして判定する**。**判定は提案**で、オペレーターがGoogleマップで位置を確認してエリアを確定する。
- **空き確認**: 営業時間 9:00〜19:00、30分刻み、訪問は60/90/120分。**訪問の前後30分は移動時間として確保**。鑑定士の予定と確定済み予約から空きを判定。休みは選べず表示。**出勤する時間が短い日**も反映する（休みの時間には訪問が入らない）。**勤怠は「休み（終日）」と、出勤する時間（例 13:00〜19:00・17:00〜19:00・9:00〜15:00）で持つ**。午前休・午後半休・午後出社といった区別はせず、出勤する時間の外（前・後ろ）を、どの画面でも**斜線の「休み」**で塗る（名前の横に、午後出社などの札は付けない）。終日休みの日は、列全体に「休み」の札を出す。**名前の下の件数は、休みの人は「0件」**（「休み」を近くに2か所書かない）。空き開始時刻は人数つきで一覧。
- **カレンダー**: 1週間ごとの週表示（1行の一覧）と、日別表示（鑑定士ごとの列）。鑑定士の顔写真・ランク・得意分野・前の訪問からの距離（前の訪問がなければ距離は出さない）を表示。**どの枠を選ぶかはオペレーターが決める**（システムが候補をあらかじめ選ぶのはOK）。
- **枠を選んだときの移動（日別表示）**: 空き枠を押すと、カレンダーのすぐ上に、その鑑定士の**前の訪問の住所から今回の住所までの距離（km）と所要時間**が出る。あわせて、前の訪問の終了から今回の開始までの**余裕（分）**を出し、**移動時間が余裕を超えるときは「間に合いません（あとN分足りない）」と警告**する（警告だけで、選ぶことはできる）。直後に訪問があれば、そこへの距離も出す。前の訪問がなければ「前の訪問なし」とだけ出し、営業所からの距離は出さない。住所が未入力なら、入力を促す。**距離・所要時間はダミーの概算**（住所の文字から決まる代用座標。0.4章）で、本実装では枠を押すたびにGoogleマップの2点間の距離で計算する。
- **公平な配分**: **女性のお客様は客単価が高いため、今月の「女性のお客様の担当件数」が少ない鑑定士をおすすめ**する（男性のお客様は担当件数の少ない順）。おすすめ以外を選ぶと、より担当の少ない鑑定士がいることを知らせる。
- **鑑定士にはランク（SS・S・A・Bの4段階、仮の設定）と得意分野**がある。大阪エリアは鑑定士10名。実績・担当件数はダミー。
- **仮確定**: 通話を終えても**自動確定しない**。枠と担当の最終決定はオペレーターが行う。

### 2.2 仮確定後の変更・取消（折り返しの電話）

お客様から「やっぱりやめる」「日を変えたい」と電話が来ることがある。

- 電話番号で既存の受付を見つけ、**全項目を変更**・取消ができる。取消は**理由つきで記録を残す**（理由: お客様のご都合・入力ミス/重複・会社の都合・その他）。履歴が残る。
- **確定済みをオペレーターが変更すると、仮確定に戻り、配車係に知らされる**。

### 2.4 音声入力デモ（今後の拡張）

通話デモは別ウィンドウ（`?demo=1`）。台本を1発話ずつ／最後まで一気に進められ、お客様の発話から項目を拾って入力欄に自動セットする。**あくまでデモ。基本はオペレーターの手入力で完結させる**前提で、デモは通話終了でも訪問を自動確定しない。
