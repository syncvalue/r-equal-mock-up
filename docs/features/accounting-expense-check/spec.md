### 4.2 経費精算（営業サポートの一次チェック）

**営業サポートが、日ごと・鑑定士ごとに、前日までに提出された記録の入力漏れ・入力ミスを確認する**（`src/dailyCheck.js`、画面 `accounting/claimsTab.js`）。**確認の単位は「鑑定士×日」**（経費1件ずつではない）。

- **対象日**: 初期値は**前日**。◀▶・「前日」ボタン、または**カレンダー**（日付のボタンで開く）で切り替える（今日より先は選べない）。**カレンダーの日付には、提出があった日に印を付ける**: 赤「要n」＝赤の指摘がある未チェックの鑑定士の数（要対応）／黄「未n」＝それ以外の未チェックの数／緑「✓」＝すべてチェック済み。月は ◀▶ で切り替える（`monthGrid`・`dayBadges`）。その日に**始業した鑑定士**が一覧に並ぶ（営業所で絞り込める）。状況の絞り込み: 未チェック／チェック済み／差戻し／すべて。一括は、**未チェックで指摘が1つもない鑑定士**だけ。
- **一覧**: 鑑定士・前日繰越金・終業時の所持金・過不足・経費・お客様への支払・指摘（要対応＝赤／確認＝黄の件数）・状況。行を押すと、下に**詳細**が出る（初期は先頭の行）。
- **詳細で確認するもの**:
  - **現金の照合**: 前日繰越金（帳簿）→ 始業時に数えた金額（前日繰越金との差異）→ ＋引き出し金額（補充金）→ − 経費 → − **お客様への支払（買取代金）** → ＝ 帳簿上の所持金 → 終業時に数えた金額（過不足）。始業・終業の理由と、鑑定士のコメントも出す。**終業時に数えた現金の写真**も見られる。
  - **経費**（ガソリン代など。買取代金は含まない）: 確認・時刻・種類・金額・内容・領収書の写真（**サムネイル。押すと拡大表示**。外側・✕・Escで閉じる。終業時の現金の写真も同じ）・**インボイス**（適格請求書のレシートなら「インボイス」、そうでなければ「対象外」。1.3）・確認のポイント。
  - **お客様への支払**（行の「＋／－」で、**買取の内訳**（商品・ランク・点数・金額と合計）を開閉する。内訳は、訪問終了時に買取代金の経費へ記録する。以前の記録には内訳がない）: 買取代金（訪問終了時に自動で経費に計上されるもの）をお客様ごとに。いまは、金額の突き合わせ先（契約書など）がないため、**確認のポイントは付けない**（一覧と合計で見る）。
- **確認のポイント（指摘）**: 経費ごと＝領収書の写真がない（危険。経理代行は除く）／**1万円以上**の高額（警告。`HIGH_EXPENSE`）／用途が「その他」（情報）／内容の記入がない（警告）。1日ごと＝**終業・日報が未提出**（危険）／**数えた現金の写真がない**（危険）／始業時の差異・終業時の過不足・補充金の未引き出し（引き出しが補充金を超える）・残高がマイナス・所持金が多い（4.1と同じ）／**前日繰越金が、前日の終業時の所持金と一致しない**（警告）。
- **1件ずつの確認（証跡）**: **経費・お客様への支払は1件ずつ、終業時の現金は「写真と金額が一致していることを確認」を押して**、確認した記録（確認した人・時刻）を残す（`rq-mock-item-checks`）。押すたびに、確認した／していないが切り替わる（チェック済み・差戻しの後は押せない。未チェックに戻せば直せる）。終業時の現金の確認は、日報が提出され、現金の写真がある日だけ必要。**経費・お客様への支払・現金がすべて確認済みでないと、チェック済みにできない**（「1件ずつの確認 n／m」を出す）。**一括でチェック済みにするときは、その鑑定士の1件ずつの確認も、すべて確認済みにする**。詳細は**縦に並べる**（現金の照合 → 経費 → お客様への支払 → 現金の写真）。内容が折り返されないよう、経費の表とお客様への支払の表は、横幅いっぱいに出し、列の幅をそろえる。
- **チェック済みにする**: 指摘のうち**鑑定士に直してもらわないとできないもの**（領収書なし・現金の写真なし・日報未提出。`blocks`）があるときは**押せない**（差戻す）。差異・過不足・未引き出しなどは、理由を見たうえでチェック済みにできる。**差戻す**は**理由必須**（鑑定士に伝える内容）。チェック済み・差戻しは「未チェックに戻す」で戻せる。
- **メニューの件数**は、**前日までの未チェックの鑑定士の数**（今日の分は、まだ提出前なので数えない）。
- チェック結果は、鑑定士×日ごとに保存（`rq-mock-daily-checks`、記録した人・日付つき）。**チェックは確認の記録で、帳簿には載せない**（経費は鑑定士の所持金から出ていて、補充金として振り込んだ時点で帳簿の支払に入っているため）。**差戻しの理由は、鑑定士のタブレットに出る**（下の「鑑定士による修正」）。**一次チェックのあと（経理担当による二次チェック・確定）は、まだ決めていない**。

**ボール（誰の対応待ちか）と忘れ防止**（`src/ball.js`）: 経費精算の（鑑定士×日）ごとに、**いま誰が対応する番か**を決め、持っている人に**バッジ・お知らせ・点滅**を出す。
- **経理部の番**: 未チェック／鑑定士が修正した（もう一度確認）／鑑定士から返信・質問があった／**日報が未提出の過去日**（確認・差戻しが必要）。
- **鑑定士の番**: **差戻し**（直すまで）／経理部の質問への返信待ち（経理部が最後に話した未チェックの日）。
- **誰の番でもない**: チェック済み／提出前の今日の分。
- **経理部の表示**: ヘッダーに赤く点滅する「対応待ち n件」（どの画面でも。押すと、いちばん古いものを開く）／メニューの経費精算に「対応待ち n」／経費精算の上部に、**古い日から**の一覧（日付・鑑定士・理由・**2日以上たったら「n日経過」**・「開く」）／一覧の各行に「経理部の番」「鑑定士待ち」／**ブラウザのタブの題名に「(n)」**。対応待ちがないときは、緑の「✓ 対応待ちはありません」。営業所で絞り込める。
- **鑑定士タブレットの表示**: ヘッダーに赤く点滅する「経費の対応待ち n件」（訪問中の画面を除く）／メニューの経費管理に「対応待ち n」と、☰の点／ダッシュボード上部の赤いお知らせ（理由・経過日数つき）／タブの題名の「(n)」。

**経理部と鑑定士のやり取り（チャット）**（`src/expenseChat.js`・`src/expenseChatView.js`、保存は `rq-mock-expense-chats`）:
- **日ごと・鑑定士ごとに、1つのチャット**。経理部は、経費精算の**一覧の「やり取りを開く」または詳細の「○○さんとやり取りする」から開く、モーダル**（4.2）で、鑑定士は、タブレットの**経費の修正の画面**（経費管理・ダッシュボードのお知らせから開く）から、メッセージを送る。**鑑定士は左、経理部は右**（営業サポートは経理部と同じ扱いなので、「経理部」と表示）。
- **差戻し・チェック済み・鑑定士の修正は、記録としてチャットの中央に残る**（差戻しの理由も、ここに出る）。
- **モーダル**（経理部）: チャットは、画面に埋め込まず、**モーダル**で開く（外側・✕・Escで閉じる。**Enterで送れる**（日本語の変換中は送らない）。開いている間は、読んだことになる）。**補充の依頼のチャットも、同じモーダル**（完了した依頼は、送れない）。
- **新着**: 経理部の一覧にやり取りの件数と「新着 n」（相手の未読）、鑑定士のお知らせ・修正の一覧に「新着 n」を出す。画面を開いている間は読んだことになる。経理部のメッセージが届くと、鑑定士のタブレットにトースト（開いたままでも反映）。チェック済みの日も、やり取りは続けられる。
- **文章のみ**（写真・既読の表示・メッセージの削除は、まだない）。

**鑑定士による修正**（`src/reviseView.js`、`reviseExpense`・`reviseRemove`・`src/dailyCheck.js` の `revisableDays`・`canRevise`・`afterRevise`）:
- **営業サポートがチェック済みにするまでは、鑑定士が、提出（終業）済みの日の経費を直せる。チェック済みになると直せない**（未チェック・差戻しは直せる）。経理部で「未チェックに戻す」と、また直せる。
- **お知らせ**: 差戻しになると、鑑定士タブレットの**ダッシュボード上部に赤いお知らせ（日付・理由・「経費を修正する」）**が出る（開いたままでも、差戻しの瞬間にトーストで知らせる）。**経費管理**にも、直せる日の一覧（差戻し＝理由つき／確認待ち）が出る（終業後の画面にも）。
- **直せること**: 経費の**編集**（種別・金額・内容・領収書の写真・インボイス）・**削除**・**追加**。**買取代金（自動計上）は直せない**。直すと、**帳簿上の所持金・終業時の過不足・日報の経費合計を計算し直す**（**終業時に数えた金額は変わらない**ので、金額を直すと過不足が出ることがある）。始業・終業の現金、日報の提出は、ここでは直せない。
- **直したあと**: 差戻しの日は**自動で未チェックに戻り**（営業サポートが、もう一度確認する）、直した経費の**1件ずつの確認は外れる**（現金の確認はそのまま）。
- **提出前（日報が未提出）の日は対象外**（営業サポートの指摘は「日報が未提出」のまま。過去日の日報を、あとから提出する機能はまだない）。
