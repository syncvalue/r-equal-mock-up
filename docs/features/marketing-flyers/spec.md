## 12. マーケティング部

**業務の前提**: このシステムのお客様は、**新聞折込・ポスティング・DM・はがきのチラシを見て、電話をかけてくる**のが通常の流れ。マーケティング部は、**チラシの作成・登録と、反響管理（どのチラシが効果的だったか）**をする。画面は `/marketing/`（`marketing/`）。左メニュー（☰）で、「ダッシュボード」（最初の画面）「チラシ」「配布カレンダー」「反響管理」を切り替える（ヘッダーに「マーケティング部 › 機能名」）。**ログインがある**（2026-11-19 に追加。店舗・倉庫と同じ作り）: マスタ管理の社員（マーケティング担当）のログインID（デモ: `mk01`・`mk02`）で入る。**パスワードは、空でなければ何でも通る**（モック）。ログイン状態は**タブを閉じるまで**。**無効にした社員・ほかの役割の社員は入れない**。ヘッダーに、ログインした人の名前と「ログアウト」を出す（以前の、人を切り替えるデモ用の選択欄は廃止）。ログイン画面のID `MKT-04`（「アカウント」に、デモ用のID一覧）。役割は**マーケティング担当**、所属は**マーケティング部**。

- **チラシのID**: チラシには**固有のID（頭文字＋4桁）**が印刷されていて、お客様が電話で伝える。頭文字は、**新聞折込＝N・ポスティング＝P・DM・はがき＝D**。**IDは、システムが、配布方法ごとに、いまの最大の番号の次（1001から）を採番**する（人は入力しない）。**コールセンターの受付（2.1）の「来電のきっかけ」のチラシIDと同じもの**。

### 12.1 チラシ（登録・一覧）

- **項目**（`src/flyers.js`。保存は `rq-mock-flyers`）: チラシの名前（必須。重複不可。例: 11/26号 着物・骨董）・配布方法（必須。新聞折込／ポスティング／DM・はがき）・広告種別（任意。受付の「広告種別」と同じ区分）・配布するエリア（必須。文字で自由に書く。例: 大阪府（吹田市・豊中市））・配布の期間（はじめ・おわり。両端を含み、1日だけでもよい）・部数（必須。1以上の整数）・費用（円。空なら0円）・**入稿期限（任意）**・**進捗**・**デザインデータ（画像かPDFを1つ。任意）**・メモ・有効／無効。**削除はなく、有効・無効だけ**。
- **配布方法は、登録したあとは変えられない**（IDの頭文字と結びついているため。別の方法のときは、新しく登録する）。IDも変わらない。
- **デザインデータ**（2026-11-19 に追加）: チラシの画像（png・jpeg・webp・gif）かPDFを1つ保管できる（**500KBまで**。モックはブラウザに保存するため。本実装では、ファイルの保管場所に置き換える）。一覧に、画像は小さく、PDFはリンクで出し、押すと保存できる。変更のとき、指定しなければ、いまのものを残し、「外す」で外せる。
- **あらかじめ登録して、1件ずつ配布まで進める**（2026-11-19 に依頼者が決定）: **今後配布する予定のチラシも、先に登録できる**（やることを、あらかじめ登録しておく）。**進捗は4段階: 未着手 → 制作中 → 入稿済み → 配布済み**。新しく登録すると未着手（すでに進んでいるものは、登録のときに進捗を選べる）。一覧の「**進める**」（ボタンの名前は、次の進捗に合わせて「制作に進める」「入稿済みにする」「配布済みにする」）で1つずつ進め、「戻す」で1つ戻せる。進捗がない古い保存は、配布のおわりが過ぎていれば配布済み、そうでなければ入稿済みとして読む。
- **入稿期限**: 印刷会社・新聞社などへ、チラシのデータを入稿する期限。**配布のはじめの日より後にはできない**。未着手・制作中のチラシで、期限が今日なら橙、過ぎていれば赤で示す。ダッシュボードの「本日中に入稿するチラシ」に使う。
- **一覧**: 札は**進捗**（未着手・制作中・入稿済み・配布済み。入稿済みで配布の期間中は「配布中」。無効は「無効」）。**進めることが残っているチラシが上**（入稿期限の早い順）、次に配布済み（新しい順）、無効。「変更」で、左のフォームに読み込む。「今日配布」の件数を、一覧の見出しとヘッダーに出す。
- **受付との連動**: 登録したチラシのIDは、コールセンターの受付の**チラシIDの欄**で、そのまま使える（欄の候補に出る。入れると、チラシの名前が出て、来電のきっかけが決まる）。受付の記録には、IDと、チラシの名前が残る。**これまでの4つのチラシ（N1012・N1019・P1015・D1001）は、見本として登録済みで、きっかけの文言は変えない**。
- **見本**（ダミー）: 上の4つに加え、**今日配布の新聞折込（N1020）と、今日をまたぐポスティング（P1016）**。

### 12.2 反響管理

**どのチラシが効果的だったか**を見る。**反響＝そのチラシのIDで、コールセンターが受けた受付**（`src/flyers.js` の `flyerStats`）。

- **受付**＝受付の件数（**取消も、電話が来たので数える**）。**確定**・**取消**は、内訳。**反響率＝受付÷部数**。**1件あたりの費用＝費用÷受付**（受付がないチラシは出さない）。
- **配布方法ごとの合計**（新聞折込・ポスティング・DM・はがき）を、上に3つのカードで出す。方法を見直す材料。
- **チラシごとの一覧は、効果の順**（1件あたりの費用が安い順。受付のないチラシは最後）。配布方法で絞り込める。
- **チラシの行を押すと、日ごとの受付**（配布のあと、何日目に電話が来たか）を出す。
- **買取の金額・粗利でも測る**（2026-11-19 に追加）: 一覧に、**成約**（訪問で買取があった件数）・**買取額**・**粗利**・**損益（粗利−費用）**を出す。**粗利＝売った商品の、想定販売価格−買取額**（想定販売価格を入れた商品だけ）。費用対効果＝粗利÷費用。並びは「効果の順（1件あたりが安い順）」と「損益の順」を切り替えられる。配布方法ごとのカードにも損益を出す。
- **広告は、アポ（受付）に結びつく。商品には、直接つなげない**（2026-11-19 に依頼者が決定）。**チラシ→アポ→訪問→買い取った商品**とたどる（受付のIDと、鑑定士の予定・訪問のIDが同じ。`receptionDetails`）。チラシの行を押すと、日ごとの受付と、**アポごとの買取**（受付番号・訪問日・お客様・状態・買い取った商品・買取額）が出る。
- **デモ**: モックには、受付のあとの訪問の記録がほとんどないため、**訪問の記録がない確定の受付には、見本の買取の実績を入れる**（「デモ｜見本の買取実績を含む」。同じ受付には、いつも同じ値）。訪問の記録があれば、そちらを使う。

### 12.3 オペレーターへの「今日配布のチラシ」

**今日、どのチラシが配布されているかが、事前に分かれば、どこからの電話が増えそうかを見込める**（オペレーターの要望）。コールセンターの**受電の画面の左上に、「今日配布のチラシ」**を出す（`callcenter/todayFlyers.js`）。

- 見出しと一覧には、**有効で、配布の期間に今日が入るチラシ**（ID・配布方法・名前・配布するエリア）。ないときは「今日配布のチラシは、ありません」。
- **開くと、さらに2つ**（2026-11-19 に依頼者が決定）: **明日の配布予定**（有効で、明日が期間に入るチラシ）と、**過去の反響の傾向**（受付の**曜日ごとの件数**の棒と、**反響率の高いエリア**の上位3つ。エリアは、チラシの配布エリアの都道府県ごと）。
- 開閉は「▼ 開く／▲ 閉じる」（右上）。開閉は、おぼえておく。「?」に、使い方の説明。
- **変更（2026-11-19）**: 当初は「今日の分だけ」だったが、明日の予定と過去の傾向も見せる。**費用・買取額・粗利・損益など、お金の数字は、オペレーターには見せない**（マーケティング部の画面で見る）。閉じているときは、今日の分だけ。

### 12.6 ダッシュボード

**マーケティング部が追いたい数字を、ひと目で見る**（2026-11-19 に追加。メニュー「ダッシュボード」。ログイン後の最初の画面）。`marketing/dashboardTab.js`、ロジックは `src/flyerDashboard.js`。メニューの項目に、**本日中に入稿するチラシの数**（期限切れを含む）の印が付く。

- **上の4つの数字**: 本日配布のチラシ（件数）／本日中に入稿（件数。期限切れを含み、あれば赤）／今月の受付（先月との差つき）／今月の損益（今月の受付の粗利 − 今月配布するチラシの費用）。
- **本日配布のチラシ**: 一覧（ID・配布方法・名前・エリア・部数）。
- **本日中に入稿するチラシ**: 未着手・制作中で、入稿期限が**今日**または**過ぎている**もの（期限切れは赤）。**「進める」で、その場で進捗を進められる**。**3日以内に入稿するチラシ**も、下に出す。
- **直近3か月の反響 上位N件**（N＝3・5・10を切り替え。既定5）: **今日から3か月前の同じ日まで**の受付の件数が多いチラシ（取消も数える）。受付の件数・反響率つき。反響のないチラシは出さない。
- **進捗**: 有効なチラシの、進捗ごとの件数。
- 見るだけではなく、入稿期限のチラシは、ここから進められる。画面ID `MKT-05`。

### 12.5 配布カレンダー

**日ごとに、どのチラシを配るかが、月の表で分かる**（2026-11-19 に追加。メニュー「配布カレンダー」）。`marketing/calendarTab.js`、ロジックは `src/flyerCalendar.js`。

- 日曜はじまりの月表示。前の月・今月・次の月に移れる。マスには、その日に配布する**有効なチラシ**（ID・名前）を最大3件出し、超えたら「ほかN件」。**配布の期間が複数日のチラシは、期間の毎日に出る**。今日は丸で印。
- **日を押すと、下に、その日のチラシの詳細**（ID・配布方法・名前・エリア・部数・期間）。
- 見るだけ（登録・変更は「チラシ」）。画面ID `MKT-03`。

### 12.4 モックの限界・確認が要ること

- **区分（一般・責任者）**: マーケティング担当にも区分がある（R-4）。**責任者にだけできること**は、決めていない（仮: 一般と同じ）。
- **チラシの作成**: デザインそのものを、このシステムで作る機能はない（デザインデータの**保管**まで）。制作の進み具合の管理は扱わない。
- 反響の集計は、モックの**ダミーの受付**から。本実装では、受付のDBから集計する。デザインデータは、本実装ではファイルの保管場所へ。
- 画面ID: `MKT-05`（ダッシュボード）・`MKT-01`（チラシ）・`MKT-03`（配布カレンダー）・`MKT-02`（反響管理）・`MKT-02-1`（チラシを選んだ日別）・`MKT-M01`（メニュー）。受電の「今日配布のチラシ」は、受電の画面（CC-01）の一部。
