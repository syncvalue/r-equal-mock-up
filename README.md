# 出張買取アプリ（モックアップ）

出張買取の営業担当がタブレットで使う業務アプリのモックです。Vite + vanilla JS + Tailwind CSS（CDN）。
データはブラウザの localStorage に保存され、外部へは送信されません。

## 起動

```
docker compose up --build   # http://localhost:5173
```

Docker を使わない場合は `npm install` のあと、開発サーバーを起動します（`package.json` の dev スクリプト）。
Tailwind は CDN 読み込みのため、ネット接続が必要です。

## 画面

| 画面 | URL | 内容 |
|---|---|---|
| 画面一覧（トップ） | `/` | 各画面への入口（要件定義用）。コールセンターは、`?tab=dispatch`（配車確定）・`?demo=1`（音声入力デモ）・`?area=`・`?day=` で、その画面を直接開ける |
| 買取アプリ（タブレット） | `/tablet/` | 始業・終業、経費管理、今日の予定、現地買取の一連の流れ、メインメニュー（準備中の機能あり） |
| 本社 査定部（PC） | `/honsha/index.html` | 買取明細のリアルタイム表示、査定依頼への回答、承認、コメント送信、営業への入金登録と日報・現金過不足の確認 |
| コールセンター（PC） | `/callcenter/index.html` | 受電の聞き取り、訪問先のエリア判定、営業の空き確認、女性のお客様の担当が偏らない担当営業の選定、訪問の確定 |
| GMOサイン（ダミー） | `/gmosign/index.html` | 本人確認書類の登録と、契約書（A4）の印刷。チェック項目・署名は、印刷した紙にお客様が記入する想定 |

各画面は同一ブラウザの localStorage を介して連携します（別タブで開いて確認します）。
各画面の下部にある「（デモ用）データ初期化」で、マスタ以外のデータを消せます。

## 1日の流れ（始業・終業と経費）

- **始業**: 始業するまで、現地買取は使えません（他の機能は始業前・終業後も使えます）。アプリの初期画面は始業画面で、本社からのお知らせを確認できます。前日からの繰越金を実際に数えて照合し（ずれがあれば理由が必須）、飲酒・体調・身だしなみなどの点検項目をすべてチェックすると、点検結果が記録されて業務を開始できます。
- **所持金** ＝ 前日繰越金 ＋ 本社からの入金 − 経費。入金は本社画面の「💴 入金・日報」から登録します（毎朝の定例入金のダミーあり）。
- **経費管理**: 種別（ガソリン代・昼食代・備品購入・高速/駐車場・交通費・その他）と金額を入力し、レシートの写真を添付して計上します。買取代金は、訪問終了時に自動で計上されます。
- **終業**: 帳簿上の残高と、実際に手元にある現金を照合し（ずれがあれば理由が必須）、終業点検をして日報を提出します。日報には現金収支・経費内訳・訪問と買取の実績が自動集計されます。終業後は、現地買取と経費の計上ができなくなります。翌日の繰越金は、終業時に数えた金額です。

- **不在・日程変更など**: 訪問開始の画面から「訪問できなかった場合」を記録できます（不在／日程変更の依頼／お客様都合のキャンセル／その他）。訪問実績として日報・本社画面に反映され、営業の責任ではないため業績には影響しません。

## 現地買取の流れ

お客様確認 → 説明事項（査定前の説明と、他商品の提案可否の確認）→ 買取明細（商品マスタから選択／AIカメラ／本社査定／AI査定）→ 買取商品の確認（査定部の承認が必要）→ シール紐づけ → GMOサイン送信・訪問終了

## 商品の持ち帰り（入庫）

訪問を終了すると、シールを貼った実物1点ごとに「入庫待ち」が登録されます。事務所に戻ったら、メニューの「商品の持ち帰り」で、シールのQRを読み取りながら倉庫に入庫します。

- 1日分でも、2〜3日分まとめてでも入庫できます（「対象日」で絞り込み）。
- 保管場所を選んでから、カメラで連続読取（モック）／スキャナ・手入力（Enterで入庫）。
- 入庫済み・他の営業の商品・未登録のシールは、エラーで知らせます。手元にない商品は「所在不明」として報告できます。
- 動作確認用に、画面右下の「（デモ用）過去2日分の入庫待ちを追加」でダミーを作れます。

## コールセンター（受付・配車）

受電システムで録音している通話の内容を聞き取りながら入力し、訪問日と担当営業を決める画面です（Googleマップでの運用の置き換え）。

- **ヒアリング**: お客様（性別は必須）、何を見て電話してきたか（チラシの号など）、売りたいもの、立会い、訪問時の注意、訪問の希望日時。電話番号が過去のお客様と一致すれば、情報を引用できます。
- **エリア判定**: 訪問先の都道府県から担当エリア（大阪／兵庫・京都／関東／東海）を決め、そのエリアの営業だけを候補にします。担当のない都道府県は「対応エリア外」とし、他エリアの営業を例外として選べます。電話は全国から来るため、お客様の住所で判定します。
- **空き確認**: 営業の予定と、確定済みの予約から、希望日時に空いている人を判定します。訪問の前後30分は移動時間として確保し、営業時間は9:00〜19:00です。空いている開始時刻は人数つきで一覧できます。
- **公平な配分**: 女性のお客様は客単価が高いため、今月の「女性のお客様の担当件数」が少ない営業をおすすめします（男性のお客様は、担当件数の少ない順）。おすすめ以外を選ぶと、より担当の少ない営業がいることを知らせます。
- **確定**: 確定した予約は、営業アプリの予定と、訪問開始画面・予定の詳細の「受電時のヒアリング」に反映されます。「空き状況・受付履歴」で全員の予定・今月の担当件数の確認、予約の取消ができます。
- 営業の予定と今月の担当件数の実績はダミーです。エリアの区分・営業の担当エリアは `src/dispatch.js` にまとめています（配車のロジックは画面から独立していて、`npm test` で確認できます）。

## 構成

- `src/` 買取アプリ（`workday.js`・`workdayView.js` 始業・終業・経費管理、`main.js` 状態・イベント、`views.js` 画面、`masterView.js`・`search.js` 商品マスタ検索、`ai.js` AI査定（モック）、`store.js` 画面間のデータ共有、`stock.js`・`stockView.js` 商品の持ち帰り）
- `src/dispatch.js`・`src/reservations.js` コールセンターの配車ロジックと予約データ、`callcenter/` コールセンターの画面
- `honsha/` 本社査定部の画面
- `gmosign/` GMOサイン（ダミー）と契約書の帳票
- 商品マスタ・AI査定・コールセンター受付情報は、すべてダミーデータです。
