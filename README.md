# 出張買取アプリ（モックアップ）

出張買取の営業がタブレットで使う業務アプリのモックです。Vite + vanilla JS + Tailwind CSS（CDN）。
データはブラウザの localStorage に保存され、外部へは送信されません。

機能ごとの仕様と、業務上の前提・決定の経緯は [docs/SPEC.md](docs/SPEC.md) にまとめています（引き継ぎ・仕様追加の前に読んでください）。

## 起動

```
docker compose up --build   # http://localhost:5173
```

Docker を使わない場合は `npm install` のあと、開発サーバーを起動します（`package.json` の dev スクリプト）。
Tailwind は CDN 読み込みのため、ネット接続が必要です。

## 1日の流れ（始業・終業と経費）

- **始業**: 始業するまで、現地買取は使えません（他の機能は始業前・終業後も使えます）。アプリの初期画面は始業画面で、本社からのお知らせを確認できます。前日からの繰越金を実際に数えて照合し（ずれがあれば理由が必須）、飲酒・体調・身だしなみなどの点検項目をすべてチェックすると、点検結果が記録されて業務を開始できます。
- **所持金** ＝ 前日繰越金 ＋ 本社からの入金 − 経費。入金は経理部の画面（🏦 入金処理）から登録します（毎朝の定例入金のダミーあり）。
- **経費管理**: 種別（ガソリン代・昼食代・備品購入・高速/駐車場・交通費・その他）と金額を入力し、レシートの写真を添付して計上します。買取代金は、訪問終了時に自動で計上されます。
- **終業**: 帳簿上の残高と、実際に手元にある現金を照合し（ずれがあれば理由が必須）、終業点検をして日報を提出します。日報には現金収支・経費内訳・訪問と買取の実績が自動集計されます。終業後は、現地買取と経費の計上ができなくなります。翌日の繰越金は、終業時に数えた金額です。

- **不在・日程変更など**: 訪問開始の画面から「訪問できなかった場合」を記録できます（不在／日程変更の依頼／お客様都合のキャンセル／その他）。訪問実績として日報・本社画面に反映され、営業の責任ではないため業績には影響しません。

## 現地買取の流れ

お客様確認 → 説明事項（査定前の説明と、他商品の提案可否の確認）→ 買取明細（商品マスタから選択／AIカメラ／査定依頼／AI査定）→ 買取商品の確認（査定部の承認が必要。査定依頼を出した商品は、完結してから承認）→ シール紐づけ → GMOサイン送信・訪問終了

## 店頭買取（店舗）

お客様が店舗に買取希望品を持ち込む買取です（訪問はしません）。**エリア判定・担当営業の割り当て・配車はありません。** 詳細は [docs/SPEC.md](docs/SPEC.md) の11章。

- **来店予約**: コールセンターの「来店予約（店舗）」タブで、店舗・日時・お客様を受け付けます（仮確定・確定はありません）。
- **来店（一覧）**: 店舗の画面で、待ち・対応中・これから来店の予約・完了に並びます。予約なしの来店は「飛び込み」で、お名前だけで受け付けられます。
- **買取（5手順）**: お客様確認（古物営業法の本人確認・台帳の項目）→ 説明事項 → 買取明細 → シール → 確認・支払い（GMOサインへ送信、終了前の確認）。途中で閉じても、来店ごとに続きから再開できます。
- **クーリング・オフの対象外**: 店頭買取の商品には、10日間の保管期間がなく、入庫したその日から出品できます（法律上、対象は訪問購入だけのため）。
- 完了すると、契約（GMOサイン）と、1点ごとの入庫待ちが作られ、倉庫・物流の「入庫」に出ます。レジ現金・査定部との連動は、まだありません。

## 商品の持ち帰り（入庫）

訪問を終了すると、シールを貼った実物1点ごとに「入庫待ち」が登録されます。事務所に戻ったら、メニューの「商品の持ち帰り」で、シールのQRを読み取りながら倉庫に入庫します。

- 1日分でも、2〜3日分まとめてでも入庫できます（「対象日」で絞り込み）。
- 最初に、最上段の「QRを読み取って入庫」で、カメラで連続読取（モック）。QRが読めないときは、スキャナ・手入力（Enterで入庫）。納入先の倉庫は選びません（自分の営業所と一体の倉庫に入ります）。画面は左が「入庫する」、右が一覧で、入庫した商品は消えずにグレーの「入庫済み」になり、各訪問の下に回ります（上が未入庫）。保管場所（棚）は選びません（クーリングオフ期間中は、商品ごとに分けず、全て「クーリングオフ保管棚」にまとめて保管します）。
- 入庫済み・他の営業の商品・未登録のシールは、エラーで知らせます。手元にない商品は「所在不明」として報告できます。
- 動作確認用に、画面右下の「（デモ用）過去2日分の入庫待ちを追加」でダミーを作れます。

## 倉庫・物流（商品管理・販売・返品）

営業が入庫した買取商品（シールNo.ごとの実物）を、フリマや業者に販売して利益を得るための画面です。

- **📦 商品管理**: 入庫待ち・在庫・出品中・売却済み・返品の状態で絞り込み、商品名・シールNo.・お客様名で検索できます。
  - **ページ送り**: 商品管理の一覧は、20・50・100点ずつのページに分かれます（「買取日・お客様別」では、契約の件数で分かれます）。絞り込み・検索・表示の切り替えをすると、1ページ目に戻ります。
  - **表示の切り替え**: 初期表示は「一覧」です。「買取日・お客様別」に切り替えると、最初は買取日単位・お客様（契約）単位に保管するため、新しい買取日から、お客様（契約）ごとに商品をまとめて表示します。クーリングオフのときに、すぐ探せます。
  - 商品をQRで探すと、**同じ契約（買取日・お客様）で一緒に買い取った他の商品**と、その保管場所（本社・倉庫・棚）も出ます。
  - **商品を探す（1つの検索欄）**: 商品名・シールNo.・お客様名を入力すると、一覧が絞り込まれます。シールのQRをQRリーダーで読み取る（またはシールNo.を入力してEnter）と、その商品の詳細と、買取から入庫・出品・売却・返品までの履歴が表示されます。続けて読み取れます。
  - **📷 カメラで読み取る**（モック）: 営業のタブレットのシール読取と同じ見せ方で、カメラが起動して、シールのQRを読み取ったように見せます（実際のカメラは使いません）。商品管理では、登録済みの商品から1点を読み取って、詳細を表示します。入庫タブでは、自分の倉庫で入庫できる入庫待ちの商品を、順に読み取って入庫します。
- **メニュー**: 各画面（商品管理・入庫・倉庫間移動・販売（出品）・売上管理・クーリングオフ返品）へは、画面左上の「☰」で開く、左側の開閉式メニューから移動します（営業のタブレットと同じ。項目を選ぶか、外側・✕で閉じます）。入庫待ち・受け取り待ち・返品対応中の件数が、メニューの項目に出ます。ログアウトも、メニューの下にあります。
- **倉庫マスタ**（マスタ管理の「🏭 倉庫」。倉庫・物流の画面からは、メニューの「マスタ管理」で開きます）: 倉庫は、営業所とは独立した施設として管理します（全国に複数）。営業所と一体の倉庫、倉庫のみの施設があり、倉庫のない営業所（営業のみ）もあります。倉庫ごとに、名前・所在地・営業所との関係・保管場所（棚）を登録し、有効・無効を切り替えられます（保管中の商品や有効な倉庫担当がいる倉庫は、無効にできません）。倉庫担当は、各倉庫に所属します（登録・所属の変更・有効／無効は、マスタ管理の社員で行います）。初期値は、大阪倉庫（大阪営業所と一体）、関東倉庫（関東営業所と一体）、福岡倉庫（倉庫のみ）で、兵庫・京都、東海の営業所には倉庫がありません。マスタは「データ初期化」では消えません。
- **本社（高額品の保管先）**: 本社も、倉庫と同じ保管場所の1つとして倉庫マスタに登録します（1か所だけ）。**シールの色が紫・赤の高額品も、まず営業所と一体の倉庫に入庫**し（営業は色にかかわらず同じ操作）、**そのあと倉庫間移動で倉庫から本社へ移します**（本社には、入庫ではなく移動でだけ入ります）。シールの色は、紫（最も高額）・赤・黄・緑・青の5色で、営業・店舗スタッフが選びます。高額品の判定は紫・赤だけで、黄・緑・青の扱いは同じです（青は1点では出品できませんが、今は区別しません）。本社へ移す色は、倉庫マスタ画面で変えられます。
  - 営業が買取のとき、シールのQRを読み取った商品ごとに、**シールの色を選びます**（選ばないと、次に進めません）。契約（訪問）の中に、高額品とそれ以外が混ざる場合は、高額品だけが本社、それ以外が倉庫に入ります。
  - シールの色は、基本的に営業が決めます（査定部と相談して決めることもあります）。
  - **シールの貼り替え**: シールの色が間違っていた場合は、色を変える＝シールそのものが別になるため、**商品のシールNo.（ID）も新しくなります**。入庫タブ・QRで探した商品の詳細から「シール貼り替え」で、新しいシールのQR（シールNo.）と色を記録します。古いシールNo.・色は履歴に残り、移動などの記録は新しいNo.に引き継がれます。古いシールを読み取ると、貼り替え済みであることと新しいNo.が出ます。貼り替えられるのは、入庫前・所在不明・在庫の商品です（出品中・委託中・売却済み・返品対応中・輸送中は不可）。色が変わって納入先が変わる場合（高額品になった／でなくなった）は、倉庫間移動で本社・倉庫に移すよう案内します。営業は、訪問を終える前なら、タブレットでシールを「解除」して読み取り直します。
  - 入庫は、色にかかわらず倉庫の担当が行います。本社には入庫できません（本社の倉庫担当の入庫タブに、そう出ます）。倉庫間の移動は、これまでどおりの規則です（高額品は本社だけへ、高額品以外は本社以外の倉庫だけへ移せます）。
  - 営業のタブレットでも、高額品を、ほかの商品と同じように入庫します（一覧に「高額品（あとで本社へ移動）」と出ます）。本社へは、倉庫の担当が倉庫間移動で移します。
- **ログイン**: 倉庫・物流の画面は、倉庫担当ごとにログインします（ID `wh01`〜`wh05`、パスワードは何か入力すれば可。初期値の倉庫担当は、大阪倉庫2名・関東倉庫1名・福岡倉庫1名・本社1名）。ログインすると、所属する倉庫が、入庫先と表示の対象になります（画面上部の「対象の倉庫」で、全倉庫や他の倉庫に切り替えられます）。入庫・出品・売却・返品の操作は、ログインした倉庫担当の名前で記録されます。
- **📥 入庫**: 営業から契約書（明細）とともに渡された商品を、倉庫担当が入庫します。契約ごとに、明細と実物を見比べて、一致した商品に☑を付けてから入庫します（☑は、誰がいつ付けたかが、商品の記録に残ります）。シールNo.（スキャナ・手入力）で入庫した場合は、読み取りで照合したものとして記録します。誰が買い取った商品でも入庫できます（営業は、タブレットの「商品の持ち帰り」から、自分の商品を、自分の営業所と一体の倉庫へ入庫します（納入先は選びません）。この場合、倉庫での照合の記録は残りません）。入庫先は、ログインした倉庫担当の所属する倉庫です。保管場所は、訪問買取の商品は「クーリングオフ保管棚」に固定（選びません）で、クーリング・オフの対象外の店頭買取の商品だけ、その倉庫の棚から選びます。商品には、入庫した倉庫が記録されます。
- **🚚 倉庫間移動**: 自分の倉庫の在庫を、別の倉庫へ送ります。送るときは「パック」（1つの荷物）を作り、次の流れで進めます。
  1. **商品を探す**: 送り先の倉庫を決めてパックを作り、商品を検索（商品名・シールNo.・お客様名）するか、**QRを読み取って**（QRリーダー・シールNo.の手入力でEnter・📷カメラ（モック））、パックに入れます。同じ契約（買取日・お客様）の商品を、まとめて入れることもできます。読み取った商品が入れられない場合（登録なし・貼り替え済みの古いシール・在庫でない・他の倉庫・別のパックに入っている・送り先の規則に合わない）は、理由が出ます。
  2. **パッキング**: パックの中身を確認し（外すこともできます）、配送業者（ヤマト運輸・佐川急便・日本郵便・その他）・サイズ（60〜170）・個口数（箱の数）・メモを決めます。梱包中の商品は「梱包中」になり、出品・返品・別のパックには使えません。
  3. **明細を出力**: 送付明細（パック番号・送り元と送り先・商品の一覧と買取額・合計・受領の確認欄）を印刷します。受け取る倉庫が、実物と照合します。
  4. **発送伝票・CSVを出力して、発送**: 発送伝票（お届け先・ご依頼主・サイズ・品名・個口ごとの伝票）を印刷します。**ヤマト運輸・佐川急便・日本郵便の取込用CSV**（UTF-8・個口ごとに1行・複数パックのまとめて出力も可）を出力し、配送業者のシステムに取り込んで、送り状を発行します（CSVの列は仮の並びで、実際の取込形式に合わせて調整します）。追跡番号がわかれば入力し、「発送する」で、輸送中になります。明細・伝票の出力は、日時が記録され、未出力のまま発送するときは確認が出ます。
  送る倉庫・送り先の郵便番号・住所・電話番号は、マスタ管理の倉庫で登録します（足りないと、伝票・CSVの出力のときに知らせます）。
  発送した商品は「輸送中」になり、受け取るまで、どちらの倉庫の在庫にも数えません（出品・返品もできません）。移動先の倉庫担当が、届いた商品に☑を付け、自分の倉庫の棚を決めて受け取ると、その倉庫の在庫になります。輸送中の間は、送った倉庫が取り消せます（元の倉庫の在庫に戻ります）。送れるのは在庫だけで、出品中・委託中・返品対応中の商品は、先に戻します。配送業者・追跡番号は、受け取り待ち・輸送中・履歴に出ます。移動は、商品の履歴（QRで探す）に残ります。サンプルデータでは、どの倉庫（本社を含む）の倉庫担当でログインしても、「梱包中のパック」「受け取り待ち」「送った商品・輸送中」「移動の履歴」のダミーが見えます。
- **自分の倉庫の商品だけ扱える**: 出品・売却・価格変更・返品の対応は、ログインした倉庫担当の所属する倉庫の商品だけです。他の倉庫の商品を扱うときは、先に倉庫間移動で自分の倉庫に移します（商品管理では、他の倉庫の商品も見られます）。
- **🛒 販売（出品）**: 在庫から商品を選び、販売先（メルカリ・ヤフオク・ラクマ／業者オークション・業者へ直接販売）と価格を決めて出品します。出品価格の目安は原価の1.3倍です。出品中の価格変更・取り下げ、売れたときの売却登録（実際の売価・送料・購入先。手数料は料率で自動計算）ができます。手数料率はダミーです。
  - **業者オークション（外部の市場）への販売は「委託」**です。倉庫間移動と同じ**パックの流れ**で、業者（委託先）に商品を渡します: 委託先（業者）を決めてパックを作る → ① 商品を探して入れる（検索・QR読取）→ ② パッキング（配送業者・サイズ・個口数、**商品ごとの希望価格**。原価の1.3倍の目安が入ります）→ ③ **委託明細**を出力（業者に渡すので、希望価格だけを載せ、原価・お客様の情報は載せません）→ ④ 発送伝票・ヤマト／佐川／日本郵便の取込用CSVを出力 → 「委託する」で、商品が「委託中」になります。委託中の商品は、倉庫の外にあり（商品管理には「倉庫の外」と表示）、委託先・配送業者・追跡番号が出ます。売れたら「売れた（入金）」で入金額を登録（委託手数料を引いて売上に反映）、売れ残って商品が戻ってきたら「売れ残り」で倉庫の在庫に戻し、再び出品できます。委託先（業者）は、倉庫マスタ画面で登録します（名前・郵便番号・住所・電話番号。初期値は、大阪時計オークション・東京ブランド市場・関西貴金属市場）。高額品も委託できます（納入先の規則は、倉庫間の移動だけです）。フリマ・業者への直接販売は、委託ではなく、倉庫から発送・引渡しします。
- **売れた商品の購入者への発送**（販売（出品）画面の下側）: フリマ・業者への直接販売で売れた商品は、**発送待ち**になります（委託先の市場で売れた商品は、市場が購入者へ送るので、対象外です）。倉庫間移動・委託と同じ**パックの流れ**で発送します: 購入者（名前・郵便番号・住所・電話番号。フリマの取引画面・業者の注文から転記）を決めてパックを作る（発送待ちの商品の「この商品を発送する」から、そのまま作れます）→ ① 発送待ちの商品を探して入れる（検索・QR読取）→ ② パッキング（配送業者・サイズ・個口数）→ ③ **納品書**を出力（購入者に同梱するので、商品名と金額（売価）だけを載せ、原価・買い取ったお客様の情報・シールの色は載せません）→ ④ 発送伝票（敬称は「様」）・ヤマト／佐川／日本郵便の取込用CSVを出力 → 追跡番号を入れて「発送する」。商品は売却済みのままで（売上は変わりません）、発送の日時・追跡番号が記録され、商品の履歴（購入者へ発送）に残ります。売上管理の一覧に、購入者への発送の状況（発送待ち・発送済み）が出ます。購入者の情報は、梱包中のパックの画面で直せます。
- **💹 売上管理**: 今日・今月・全期間の売上・原価・手数料・送料・利益・利益率を、販売先別・カテゴリ別に確認できます。集計の対象は、自分の倉庫（初期値）・他の倉庫・**会社全体**に切り替えられ、会社全体では、倉庫別の内訳も出ます。
- **📷 商品の写真の登録**: 商品管理（一覧・詳細）と入庫の一覧で、商品の写真を押すと、撮影・選択して登録（撮り直し）できます。誰がいつ登録したかが残ります。未登録の商品は「未登録」の印が付き、商品管理の「写真未登録」で絞り込めます。この写真は、クーリングオフの電話でお客様と商品を確認するときに使います（どの倉庫の商品でも登録できます）。
- **↩ クーリングオフ返品**: 訪問購入のお客様は、書面を受け取った日（買取日）から8日間、契約を解除できます。お客様の通知は郵送で届くため、余裕を見て**買取から10日間**は、販売せずに保管します。
  - 保管期間（10日間）の商品は**出品できません**（商品管理に「○/○まで出品不可」と表示）。期間を過ぎた入庫済みの商品から出品できます。
  - **依頼は、コールセンターの「クーリングオフ」タブで作ります**（倉庫の画面には、受付の入力欄はありません）。倉庫の画面は**依頼の一覧と詳細（モーダル）**です。一覧は、お客様名・電話番号・商品名などで検索でき、すべて／未対応／対応中／完了・対応不可に絞れます。**未対応（回答待ち・返送待ち・コールセンターからの未返信のメッセージ）は、上部の帯・行の色・メニューの件数で分かります**。詳細には、その依頼のやり取り（受電・回答・返送・完了と、コールセンターとのメッセージ）が**チャット形式で時系列**に並びます。倉庫担当は、①**問い合わせに回答**（返送できる／対応できない＝理由が必要）→ ② 返送済み（追跡番号）→ ③ お客様からの買取代金の返還を確認して完了、の順に対応します。完了した商品は「返品済み」になり、在庫から外れます。
  - 対応できないと回答した依頼は「対応不可」で終わり、商品は元の状態に戻ります。売却済みの商品の依頼も「対応不可」です。
  - 保管期間（10日間）を過ぎた商品も依頼は作れます（「期間超過」の印が付き、倉庫が個別に判断します）。輸送中・梱包中の商品は、届く・発送が済むまで依頼できません。
  - 契約の商品が、複数の保管場所（本社と倉庫）に分かれていても、契約全体で依頼を作れます。保管場所ごとの依頼に分かれ（お客様から返していただく代金は、契約全体の合計）、それぞれの倉庫・本社の倉庫担当が回答・返送・完了の対応をします。
- 初めて開いたときに、サンプルデータが入ります（画面右上の「サンプルデータを入れ直す」で入れ直し。営業が登録した入庫待ちの商品は残ります）。ロジックは `src/warehouse.js` にまとめ、`npm test` で確認できます。

## コールセンター（受付・配車）

受電システムで録音している通話の内容を聞き取りながら入力し、訪問日と担当営業を決める画面です（Googleマップでの運用の置き換え）。

画面（新規受付・訪問カレンダー・配車確定・クーリングオフ・来店予約）の切り替えは、ヘッダー左の「☰」から開く左メニューで行います（件数の印つき）。

- **ヒアリング**: お客様（性別は必須）、何を見て電話してきたか（チラシの号など）、売りたいもの、立会い、訪問時の注意、訪問の希望日時。電話番号が過去のお客様と一致すれば、情報を引用できます。
- **郵便番号から住所の候補**: 郵便番号を7桁入れると、欄の下に住所の候補が出ます。押すと住所に入るので、番地は続けて入力します（候補はモックの小さな表からで、住所は自由に直せます）。
- **枠を選んだときの移動**: 日別表示で空き枠を押すと、カレンダーの上に、前の訪問の住所から今回の住所までの距離・所要時間・余裕が出ます（ダミーの概算。移動が間に合わないときは警告）。
- **エリア判定**: 訪問先の都道府県から担当エリア（大阪／兵庫・京都／関東／東海）を決め、そのエリアの営業だけを候補にします。担当のない都道府県は「対応エリア外」とし、他エリアの営業を例外として選べます。電話は全国から来るため、お客様の住所で判定します。
- **空き確認**: 営業の予定と、確定済みの予約から、希望日時に空いている人を判定します。訪問の前後30分は移動時間として確保し、営業時間は9:00〜19:00です。空いている開始時刻は人数つきで一覧できます。
- **公平な配分**: 女性のお客様は客単価が高いため、今月の「女性のお客様の担当件数」が少ない営業をおすすめします（男性のお客様は、担当件数の少ない順）。おすすめ以外を選ぶと、より担当の少ない営業がいることを知らせます。
- **確定**: 確定した予約は、営業アプリの予定と、訪問開始画面・予定の詳細の「受電時のヒアリング」に反映されます。「空き状況・受付履歴」で全員の予定・今月の担当件数の確認、予約の取消ができます。
- 営業の予定と今月の担当件数の実績はダミーです。エリアの区分・営業の担当エリアは `src/dispatch.js` にまとめています（配車のロジックは画面から独立していて、`npm test` で確認できます）。

### 訪問カレンダーと前日確認（コールセンター「訪問カレンダー」）

訪問の予定を、**エリアごと**に見る画面です。

- **週の表**: 縦に時間、横に日付（7日）。セルの色は、訪問が集中している時間ほど濃く、空いている時間ほど薄くなります（数字は訪問中の営業の人数）。
- **日を押すと、その日だけ**を、営業ごとの列で見られます（営業の予定と、受付した訪問）。
- **前日確認**: 日別の訪問を押して、**つながった／つながらなかった**と、お客様から告げられたこと（メモ）を記録します。つながらず、かけ直したときも、連絡のたびに履歴が残ります。状態は、未連絡／不通 N回／連絡済み。前日確認の日（訪問の前日）にまだつながっていない訪問は、週の表の日付の下と左メニューに「前日確認 未N」と出ます。
- お客様から日時の変更・取消を告げられたら、「受付を変更・取消する」で、そのまま受付を直せます。

### クーリングオフ（コールセンター「クーリングオフ」タブ）

クーリングオフは、お客様からの電話（専用の番号）で始まります。受けたオペレーターは、次の順に進めます。進捗は、このタブの右側の一覧で管理します。

1. **商品を探す**: お客様は「先週の金曜日に来てもらった山田ですが、そのとき売った時計を…」のように、うろ覚えで電話してきます。お名前・**電話番号**（ハイフンなし・下4桁だけでも可。買取のときの訪問のお客様の番号）・シールNo.・商品名のほか、**買取日**（直近14日を曜日つきで選べます）や**商品の種類**でも探せます（名前を外して買取日だけでも可）。結果は契約ごとに、**商品の写真を大きく**並べます（押すと拡大。お客様に「これですか」と確認します）。状態の目印（在庫・期間内／期間超過／出品中など＝倉庫に確認／売却済み＝対応不可／すでに依頼中）も出ます。見つからないときは、実際には買い取っていない可能性もあります。
2. **依頼を作る**: 返品を希望する商品にチェックを入れ、電話番号・理由・受電メモを入れて作ります。倉庫に問い合わせが届きます（売却済みの商品だけは、対応不可として記録します）。
3. **進捗を管理する**: 受電・依頼 → 倉庫の回答 → 返送 → 代金の返還、の段階を、依頼ごとに見られます。「倉庫とのやり取り」を開くと、チャットで倉庫と連絡を取り合えます（お客様からの追加の連絡など）。倉庫が回答したら、お客様に返送の予定（または対応できないこと）を伝えます。
4. お客様の手元に商品が戻り、買取代金の返還も済むと、依頼は**完了**です。
